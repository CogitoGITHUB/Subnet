* Parsing
** An unclosed block is cut at the first line inside it that opens a
registered block again.
default: keep the head block and the children it already has, put one
=UnclosedBlock= error node (empty span) at the cut, and re-parse the tail as
its own elements — so a missing =end= never eats the rest of the page.
why: the ecosystem law is that a block must not stop the reader; the
alternative (cut at end of file) loses every block after the mistake.
change it by: =notation/src/parser/partial.rs=, =block_left_open= and
=parse_recovering=.
** A =code= body is opaque and is never recovered inside.
default: nothing inside =code start= / =end code= is parsed, so a stray
=paragraph start= inside a code block is text, not a node.
why: rule D, from =syntax/first-slice-freeze.org=.
change it by: =notation/src/parser/parser.rs=, the opaque-shape test.
** The block name list is =title=, =paragraph=, =code= and nothing else.
default: any other name on a =... start= line is an
=unknown-block-name= error, not a new element kind.
why: element kinds are registered one at a time (rule B); a silent new kind
would make a page parse differently tomorrow than it does today.
change it by: =notation/src/parser/parser.rs=, =BLOCK_NAMES=.
** A =comment= is a block, not a sign.
default: =comment start= / =end comment=, whole lines only, no inline sign,
and it is NOT a registered block name yet — so the parser reports
=unknown-block-name= for it today.
why: the only comment shape anywhere in the tree's documents is a block
(=syntax/open-close-mark.org:34=); an inline sign would have been invented
out of nothing.
change it by: =notation/src/parser/parser.rs= (add the name) and
=notation/src/text/comments.rs= (=COMMENT_BLOCK_NAME=).
** =strip.rs= drops blank lines inside a paragraph.
default: the plain and rich tiers print the same words, so a paragraph
renders without its internal blank lines.
why: one stripper, one answer (rule: one file one job), and rule D keeps the
blank lines for the READER, not for the render.
change it by: =notation/src/rendering/strip.rs=, =strip_marks=.

* Addressing and the surface
** A node address is its ancestor kinds plus a 1-based ordinal.
default: =title/1= = =ancestor kind=, then that node's kind, then its
ordinal among siblings of that kind, e.g. =title/1/paragraph/2=. Decided
by the document's bytes alone, so the same text always gives the same
addresses.
why: the same text must answer the same way on every run; a clock or a run
state would make addresses drift.
change it by: =notation/src/surface/answers.rkt=, =surface-node-at=.
** A stored address breaks when a same-kind sibling is inserted above it.
default: yes, it breaks, and the surface says so in its own INDEX.
why: an authored id is the real fix and ROOT-REQUEST-D014.org is unanswered,
so none is invented.
change it by: =ROOT-REQUEST-D014.org=; then =surface/surface.rkt= and
=model/addressing.rkt=.

* Literate code
** =chunk:=, =into:= and =depends:= are NOT registered keywords.
default: they are read out of the opaque code body by
=literate/chunks.rkt= itself.
why: registering a keyword is a grammar change (rule B) and the freeze has
not been amended.
change it by: =notation/src/model/properties.rkt= and the Rust parser's
keyword table, then =literate/chunks.rkt= stops reading the body.
** A chunk-graph finding refuses the send; the order prints only when the
graph is clean.
default: =literate= prints each finding and then, only if there were none,
the send order one name per line. =send= refuses and writes nothing.
why: a wait-loop has no valid order, and printing an order anyway would be a
lie an agent could act on.
change it by: =notation/src/literate/scan.rkt= (=chunk-send-order=) and
=notation/src/entry/dispatch.rkt= (where the order is printed).
** The skip sentence is one fixed line.
default: =skip: chunk <name> → <path> — unchanged; the same content hash
<32-hex> is already written there, so nothing was sent=, spoken by
=decide-skip= and never by a caller.
why: one sentence per outcome, so a reader learns it once.
change it by: =notation/src/literate/skip-journal.rkt=, =decide-skip=.

* Generation and writing
** A target file that exists but this document's store did not send is
REFUSED, not replaced.
default: no force flag exists.
why: a literate send must never eat a file it cannot account for; the
store is the only record of who wrote what.
change it by: =notation/src/generation/write.rkt=, =require-replaceable=.
** A stale store entry warns and re-sends.
default: skip requires all three — entry exists, target still there, and the
target now hashes to what the entry recorded. Any one failing re-sends, and
a stale store also warns.
why: skipping on a stale record would leave the wrong content in place
silently.
change it by: =notation/src/literate/skip-journal.rkt=, =decide-skip=.

* Rendering
** The rich tier adds exactly one thing the plain tier lacks: =✗ line N= on
an error node.
default: no graphics tier, no image, no colour, no escape codes, no tables
or numbering, no hyperlink; a wide code line overflows rather than losing
characters.
why: the plain tier is the contract; a second dialect must not invent
grammar.
change it by: =notation/src/rendering/rich.rs= (=ERROR_MARK=, and the const
block above it).
** Emphasis is read from registered =style:= / =format:= declarations only.
default: no inline emphasis mark and no inline link inside a paragraph,
because =syntax/first-slice-freeze.org= leaves both open.
why: inventing an inline mark would pre-empt the freeze.
change it by: =syntax/first-slice-freeze.org= first, then
=rendering/rich.rs= (=EMPHASIS_MARK_LINE=, =EMPHASIS_VALUES=).
** Wrapping is the caller's width; width 0 means do not wrap.
default: =render_rich= takes the width (the spec required it); =0= is the
"no wrap" signal.
why: a phone screen and a wide terminal need different widths from the same
code.
change it by: =notation/src/rendering/rich.rs=, =render_rich=.

* Commands and exit codes
** Exit codes are 0 clean, 1 findings, 2 refused.
default: one code for every finding, however many there are; the findings
themselves name their class in words on their own line.
why: =diagnostics/report.rkt= already promises exactly 0/1/2 by name.
change it by: =notation/src/diagnostics/report.rkt= and =entry/dispatch.rkt=;
=scan-finding= would need a class field.
** =status= is not a command.
default: =status= would be =send= minus its last call, so it is not a
second name for one thing; read =literate= instead.
why: a reader should not have to choose between two names for one action.
change it by: =notation/src/entry/dispatch.rkt=, =commands=.

* Tests and the gate
** Rust tests live inside the =.rs= files as =#[cfg(test)] mod tests=.
default: no separate test crate, no new dependency.
why: the crate is zero-dependency by design; a test crate would add a
Cargo.toml and a path problem for no gain.
change it by: =notation/src/lib.rs= and the new =notation/tests/crates/=.
** Racket tests live in =notation/tests/<area>/= and run through
=gate/test-runner.rkt= from one gate stage.
default: each file gets its own area directory, mirroring =src/=.
change it by: =gate/test-runner.rkt= and the =run-tests= stage in
=gate/check.nu=.
** The gate's one-way law does not resolve relative requires.
default: it checks the requires it can see as areas and ignores
="../area/file.rkt=" forms, so a relative require between areas is
unchecked today.
why: it was written for the Racket half, where area names are visible; the
relative form only appears in the Racket half's own string requires and
was not taught.
change it by: =gate/one-way-dependency-lint.nu=.

* How to read this file
# Verdict key: REUSE carries, ADAPT re-shapes, DO NOT REPEAT did not survive.

  - This file is about mechanics: what to reach for in each language, and where each language stops.
  - The rules behind them are in general-rules.org; the device costs are in phone-problems.org.

** Racket: base language, explicit requires, contracted provides
# The smallest language plus the discipline that keeps it fast.
- What PM does: base language plus explicit requires, never the full language (M-1); every provide goes through contract-out at least at predicate level (M-3); never all-defined-out (M-4).
- The rule: the language subset and the contract boundary are chosen once, at the top of the file.
- Verdict: REUSE.
- Read at: 0.FOUNDATION.org section 4.

** Racket: the fixed module layout
# One purpose line, provide, imports, implementation, tests — in that order.
- What PM does: one-line purpose statement; provided contracts with a purpose comment per identifier; imports; implementation with important functions first; the test submodule at the very end (M-2); comments carry a signature comment per function (M-11).
- The rule: a reader learns what the module is and offers before reading how it works.
- Verdict: REUSE.
- Read at: 0.FOUNDATION.org section 4.

** Racket: one error module, one raise helper, tested messages
# Exceptions live in exactly one place, with their renderer.
- What PM does: one exception struct with kind, fields, hint and cause, in one module, with one predicate per kind (E-3); one raise helper builds the message so every raiser renders identically (E-4); every error kind has a test asserting message text and exit code (E-12).
- The rule: a single constructor plus a single renderer is what makes error output a surface you can test and promise.
- Verdict: REUSE.
- Read at: 0.FOUNDATION.org section 6.

** Racket: reading data files safely
# Reader defaults, a limited port, locations kept.
- What PM does: read-syntax with the default read parameters via a size-limited port, with reader, lang and compiled forms refused — the combination that makes reading untrusted data safe; validation errors keep file:line:col from the read-syntax form (D-3, D-4).
- The rule: reading a file other people wrote is a security boundary, and the safe configuration is the default one plus a size cap.
- Verdict: REUSE.
- Read at: 0.FOUNDATION.org section 5.

** Racket: staged writes, renames and one-writer locks
# The filesystem mechanics of crash safety.
- What PM does: temp file in the same directory then rename (F-3); staging directory on the same filesystem, verify, then rename into place (F-4); a file lock with a timeout whose failure names the lock path (F-5).
- The rule: every writer reaches for the same three primitives instead of inventing a fourth.
- Verdict: REUSE.
- Read at: 0.FOUNDATION.org section 7.

** Racket: subprocesses as argv lists, never shell strings
# Spawning without quoting bugs and without an invisible shell.
- What PM does: subprocess and friends take an argv list, never a shell string, because quoting breaks and an intermediate shell breaks kill trees; the executable is resolved first and its absence is a loud error; cwd and environment are set explicitly; the few embedded shell fragments are the documented exception (F-2).
- The rule: the shell is a program you may run, never a mechanism you pipe strings through.
- Verdict: REUSE.
- Read at: 0.FOUNDATION.org section 7; docs/NU-ADOPTION.org.

** Racket: startup cost is a feature budget
# Every dependency and every cache choice pays rent in milliseconds.
- What PM does: raco make always; a single compiled-output root outside the tree set in one place (gate/env.nu) — D-027 was reversed after measuring that one root does not re-emit stock libraries, and the old note stays in env.nu on purpose; a cold root costs one rebuild, which is what a fresh checkout costs anyway; data-lib was removed because it shipped nothing useful here and took startup from 0.299s to 1.178s; JSON is bundled and needed no package.
- The rule: an added dependency is a permanent tax paid at every process start, so it must earn its place with a measurement.
- Verdict: REUSE.
- Read at: docs/RACKET-TOOLING.org; plan/OPEN-DECISIONS.org ("D-027 reversed"); gate/env.nu.

** Racket: one shared-process test runner
# Every test file runs in one process; failure is detected by diffing counters.
- What PM does: raco test re-links libraries per file (about five seconds each on this phone), so all files run in one process and one namespace (files 2..n cost milliseconds); failure detection snapshots the framework's failed and total counters before and after each file and diffs them, so a failing check cannot read as a pass; per-file isolation is the working directory, a copy of the environment and the exit handler; a file with no test submodule is reported as NO-TESTS and counts as a pass, so a typo cannot hide a test file.
- The rule: test infrastructure never trusts "no news is good news", and per-file process isolation is a last resort, not a speed setting.
- Verdict: REUSE.
- Read at: gate/test-runner.rkt header and body.

** Racket: one printer, through narration
# User-visible output leaves the program through one door.
- What PM does: every place the tree printed was inventoried first (V-0), then the output moved behind one narration module (V-1, V-3); one-printer-lint lints the rule in code and test-body-print-lint lints it inside test bodies; narration has no off-switch (D-036).
- The rule: output is a public interface, so it has one owner and lint stages that defend it.
- Verdict: REUSE.
- Read at: docs/VERBOSE.org; gate/check.nu one-printer-lint and test-body-print-lint; plan/DECISIONS.org D-036.

** JSON: one object, one line, fixed key order
# The machine surface is a strict, boring document.
- What PM does: every command takes --format sexp or json before the command word; one object per invocation printed on one line; key order is fixed and documented; every operand is a string even when it is a number; --help has no JSON form; the MCP server and the skill read this and nothing else (E-26).
- The rule: a machine surface that is boring enough to diff is boring enough to trust.
- Verdict: REUSE.
- Read at: docs/API.org.

** Nu: pinned binary, no config file, no auto-update
# Scripts name their interpreter and fail clearly when it is absent.
- What PM does: Nu owns the scripts and new tooling; the pinned binary is at a versioned path and always runs with --no-config-file; a checker reports which binary would be used and fails clearly when none exists; nothing ever downloads or updates Nu automatically; POSIX sh survives only in the fragments embedded in a Racket child process and in the checker itself.
- The rule: a script that silently runs a different interpreter version reproduces different bugs per machine.
- Verdict: REUSE.
- Read at: docs/NU-ADOPTION.org; docs/NU-NOTES.org; gate/need-nu.nu.

** Nu 0.116.1: the measured gotchas
# Four behaviours that cost this project real time, named so they cannot repeat.
- What PM does: an environment write inside a closure is discarded — the gate had been printing failures and exiting 0 until the exit code was moved into the same scope that computed it; length and where reject string input; split row needs a list; a bare use does not bring names into scope (the member-list form does), and a use path resolves from the file's directory, not the working directory.
- The rule: a gate that decides anything is proved by a fixture that makes it fail, because side channels are exactly where verdicts die quietly.
- Verdict: REUSE.
- Read at: docs/LESSONS.org; gate/check.nu header; docs/NU-NOTES.org.

** The scope-roots seam: one reader of HOME per language, mirrored
# The Nu side and the Racket side resolve the same roots the same way.
- What PM does: one Nu script resolves the config, cache and data roots with the XDG variables, blank counting as unset, the same fallbacks and the same shape as the Racket directories module; both are the single counterpart of each other, exported deliberately (D-029).
- The rule: environment discovery has one seam per language and the two seams must agree, because they are the only code that reads HOME.
- Verdict: REUSE.
- Read at: gate/env.nu; plan/DECISIONS.org D-029; ecosystem agents/ files (one scope seam).

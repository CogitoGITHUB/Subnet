#+TITLE: AIU TERMINAL MULTIPLEXER
# One job: what this program is and what it does today.
# Every line here is proved by a command that was run; the proof is in
# the tree: the gate, the research notes and the decisions.

* What it is

Shells, panes, a layout tree, and a session holder with detach and
reattach. The holder owns the shells and the screen is a thin client:
a process that outlives the program that started it can be attached
again, so an OpenCode server, a long =pm apply= and an editor session
all keep running while the human looks at something else.

Terminals are a facade over tty: what the phone cannot promise is
written down, never assumed.

* Why it is being built first (2026-10-21)

The owner switched the priority on 2026-10-21: this program is the
foundation under the complete workflow, so the AIU-PM and the AIU
EDITOR implementation are paused until it works. Both of them say so in
their own README and TODO, with the resume conditions and the exact next
task.

* What works right now

  - The tree landed (=5a8908e7=): the package is =multiplexer/= with
    the three floor areas — =errors/= (the record, the raise, the
    render), =narration/= (events, voice, wait door, the one printer)
    and =machine/= (the HOME seam, the one-writer locks, the
    cancellation door) — every file with a header, every definition
    with a comment above it.
  - The light gate is green at 7 stages: the paren check, the text
    lint, the naming register, the banned words, the one-way area
    table, the security gate and the language split. The security gate
    prints NOTHING-TO-CHECK, because the security area does not exist
    yet — a stage that checked nothing never prints PASS.
  - The route is decided (=937a2c9e=): this phone builds Rust. The
    measured numbers are in =research/tiny-binary-probe.org= — a tiny
    binary builds in 7.9 s and starts in 23 ms, and a pty works here
    (=/dev/pts/N=). The holder is therefore written and built on this
    phone; the adopt route (herdr) stays behind the same contract as
    the fallback it already was.
  - The holder works (=abab3340=): a shell on a pty inside a session that
    outlives every client, an append-only log flushed per record, and a
    unix socket in the session's state directory. The client is a thin
    screen: it attaches, asks, reads and detaches, and it holds nothing.
    The phone proof is =tools/holder-probe/probe.nu= — after the client
    detached, the shell was still alive and still writing to the log, and
    a second client found the same session and the same shell.
  - Every one of the ten modules really loads: each was required on
    its own and answered.

* The hard rules that bind it

  - =rules/= — the owner's rules, one file each. Rule 03: the holder
    has no config and no timers. Rule 04: every wait ends on an event.
    Rule 01: never lose work — what the phone cannot do is recorded,
    not promised.
  - =plan/package-tree.org= — the register of the package: =multiplexer/=
    and every file in it, one job each. A name that is not there does
    not exist yet.
  - =plan/holder-design.org= — the holder's design: the files, the
    seam, and the five-step proof that a shell survives a detach.
  - The area law: areas lowest first (errors, narration, machine,
    security, join, devloop, tty, holder, panes, routing, layouts,
    records, client, agents, control, entry); a require points downward
    only; =join/= is the only place Rust and Racket meet.

* Build

The package is Racket for the meaning side and Rust for the hot path.
The Rust build writes its target directory outside the tree:

#+begin_example
CARGO_TARGET_DIR=$HOME/.local/state/aiu-multiplexer/target \
  cargo build --offline
#+end_example

The gate is the only entry point, and it names its stages:

#+begin_example
~/opt/nushell/0.116.1/nu --no-config-file gate/check.nu
~/opt/nushell/0.116.1/nu --no-config-file gate/check.nu --list
#+end_example

Cargo runs offline: the local registry cache holds =libc= and
=serde_json= and their dependencies, and no other dependency may be
added.

    command records, the Television channels, the dev loop, the control
    surface and the kit: the build order in =plan/build-order.org= and

  - The agent surface is the owner's addition of 2026-10-21: the MCP
    server over the holder's socket, the skill, and the OpenCode
    registration, so a true OpenCode session drives the multiplexer and
    the editor without the owner touching the terminal.
  - The =join/= seam: nothing crosses Rust and Racket yet, and the
    language-split lint keeps it that way.
  - The key routing, the command records, the agent panes, the dev
    loop, the control surface and the kit: they come with the items
    that need them.
  - Tests: the light gate only, until the owner opens them (root
    DECISIONS.org D-001).

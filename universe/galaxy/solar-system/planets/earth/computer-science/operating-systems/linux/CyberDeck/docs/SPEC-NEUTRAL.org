Target extension point: the install head symbol IS the target. =prefix=

backend; the core still treats forms as data.

(Emacs-only); =cmake= splits into the three cmake-* steps.

* 3. Install forms + PREFIX rule
Forms: (bin [SRC] DST) (lib [SRC] DST) (include [SRC] DST) (share [SRC]
DST) (man [SRC] DST) (libexec [SRC] DST) (copy-tree SRC DST) (symlink
LINK TARGET) (mode RELPATH OCTAL). Two-arg kind forms copy from staging
then own DST; one-arg forms own an already-placed path (cmake-install /
run placements). Modes: 755 bin/libexec, 644 rest, unless (mode ...)
says otherwise. Every DST/LINK must stay inside the prefix: absolute
paths and =..= escapes are rejected by the validator.
Post-install check: optional single =(check PROGRAM ARG ...)= install
form, run after placement with PREFIX in the environment and cwd set to
the prefix, under the same allowlisted env. Argv runs without a shell
(spell out sh -c when shell features are needed; relative paths resolve
under the prefix). Exit 0 is required and output is captured into the
build log: a failing check keeps the =.pm-incomplete= marker, fails the
build (exit 7), and activation stays refused.
PREFIX = the final versioned dir (~/.local/share/cyberdeck/NAME/VERSION).
There is no staging prefix and no DESTDIR relocation: builds and
placement write into the FINAL directory from the start, so every path
embedded by a build (bats bin script, .pc and cmake config files) is
already correct. The directory is created holding a =.pm-incomplete=
marker; the marker is removed only after build, placement AND the check
step all succeed. The =current= link and every profile generation never
reference a directory that still has the marker (activation refuses
marked dirs, exit 7). Atomicity comes from the link/generation swap,
not from renaming the directory (F-4 as applied: the object renamed
into place is the link, never the tree).
Consequence: moving a versioned dir still breaks baked-in prefix text.
The manifest records the prefix at install; =pm status= re-reads it and
reports =moved= (WHAT file still names the old prefix, WHERE it is,
WHY it broke, NEXT reinstall), never silently.
Assumed host tools (not pm deps, documented per spec): lua needs
gcc/ar/make; cjson needs cc/cmake/make; bats needs bash/install/coreutils.

* 4. ACTIVATION (DECIDED: profile forest with generations)
Location: $XDG_DATA_HOME/cyberdeck/profile/ (default
~/.local/share/cyberdeck/profile/), inside the proot rootfs, never on
shared storage. The engine probes at init that symlinks work there;
if not, init refuses with a plan-kind error ([VERIFY] on this phone).
Layout: profile/ holds generation dirs profile-NNN/ plus a =profile=
symlink pointing at the active one. Each generation holds REAL
directories (bin lib include share libexec man) containing symlinks to
FILES inside <pkg>/current/<path>. Never a symlink to a whole package
directory, so two packages can both provide bin/ or share/man.
Atomicity: activate builds the next generation dir, then swaps the
=profile= symlink by rename(2): one atomic step, readers never see a
half profile. Old generations stay until =pm profile-prune N= deletes
by explicit command, never by time or age (D-015). Rollback = repoint
=profile= at a previous generation (=pm rollback N=).
Conflicts: two active packages owning the same relative path fail
closed BEFORE anything changes: no precedence rules, no last-wins.
Exact message, exit 9 (activate failed; E-15 table gains 9 in STEP 5):
#+begin_example
activate: file conflict, nothing changed;
  file: bin/bats
  owned-by: bats-core 1.14.0
  claimed-by: pkg-foo 2.0
  hint: deactivate one package or pass --override 'bin/bats' PKG
#+end_example
Dev mode (STEP 4): a dev checkout appears through the SAME <pkg>/current
link (pointed at the checkout), and =pm status= flags it =dev= with the
checkout path. Activation treats dev and normal packages identically.
Explicit only: activation runs on =pm activate= and nothing else. Install,
update, rollback-stage and dev-link never touch the profile on their own.
New commands: =pm path NAME= prints that package's current directory (one
line, for scripts); =pm profile= prints the one shell-rc line to add
(PATH/MANPATH entries pointing under the profile symlink) for review
before the user sources it. =pm status= shows: active generation +
kept generations, per-package version/current/active/held/superseded/dev,
moved-prefix, stale links.

[VERIFY] rename-over-symlink under proot (ln -s NEW active.new, then
mv -T active.new active; concurrent readlink+cat reader). Real output:
#+begin_example
reader: 500 reads, 0 failures
final: gen1 -> one
#+end_example
Method: 300 swaps foreground while 500 readlink/cat pairs run
concurrent; every readlink returned gen1-or-gen2, every cat returned
one-or-two, the link never dangled. (Cross-read pairing is not asserted:
readlink-then-cat is two syscalls and may straddle a swap under ANY
kernel; per-syscall atomicity is what rename(2) guarantees and what the
probe confirms.) An earlier 400-read run of this probe was vacuous (a
stray =&= backgrounded the swaps into the wrong directory; its numbers
are discarded, not trusted). Verdict: the swap primitive holds under
proot; activation does one rename per generation switch.

* 5. Build environment (this phone: no sandbox, honestly)
Allowlist only: PATH (vault tools + /usr/bin:/bin), CC, MAKEFLAGS/JOBS,
LANG=C.UTF-8, HOME=staging-fake, PREFIX/SRCDIR/BUILDDIR pointers (S-6).
Build runs in $CACHE/cyberdeck/build/<name>-<version>-<short>/ with
src/ (vault export at pin, S-5) and build/ (out-of-tree objects). PREFIX
points at the final versioned dir, created first with =.pm-incomplete=.
Steps and placement write only under src/, build/ and PREFIX; nothing
touches the store, =current= or the profile until success. Order:
fetch, export, build steps, install placement, check step, remove the
marker, flip =current= by rename(2), and only on =pm activate= rebuild
a profile generation. A failed build leaves a marked directory that
=pm status= reports as =incomplete=; =pm clean-incomplete NAME VERSION=
removes it by explicit command, never by sweeper or age (D-015).
Interrupted builds (Ctrl-C cancel, kill -9): the marker survives, and
the NEXT explicit command touching the package reports it; exact form:
#+begin_example
build: interrupted, package left incomplete;
  package: lua 5.5.1
  dir: ~/.local/share/cyberdeck/lua/5.5.1
  marker: .pm-incomplete
  hint: rerun the build or run 'pm clean-incomplete lua 5.5.1'
#+end_example
No sandbox: proot gives no usable mount/pid/net namespaces, so builds
run as the user with full filesystem access and network present.
Mitigation is isolation-by-directory (separate staging per build) plus
env scrubbing plus exact argv in the plan. Network use by a build is
UNENFORCED and recorded as a plan assumption, not a guarantee.

* 6. Dependencies: build-time vs run-time
=deps= are run-time (needed to use the package, activation closure).
=build-deps= are build-time only (toolchain, generators; present for
configure/build steps, absent from the activation closure). The resolver
unions both for build ORDER but only =deps= for activation. Cycle and
equality tests use SYNTHETIC fixtures (T-10). None of the three proof
packages takes any edge (lua/cjson: no deps; bats: bash is an assumed
host tool, not a pm package).

* 7. D-019 OPEN (not decided): non-git inputs
v1 builds from git sources only. A build needing cargo-fetch, raco pkg,
npm, or any outside-git fetch is REFUSED at check/plan time: kind

NEXT vendor the sources into a git repo or wait for D-019. Future
options (vendored sources, hash-pinned fetch step, toolchain packages)
stay open; nothing is implemented for them now.

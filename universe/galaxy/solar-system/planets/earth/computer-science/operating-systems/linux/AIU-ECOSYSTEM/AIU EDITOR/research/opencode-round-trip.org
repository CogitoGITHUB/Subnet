#+TITLE: The OpenCode round trip on the phone
# One job: what the proot test found about reaching OpenCode from the editor, and what it cost.
# Status: current; the findings of 2026-10-20, from the test of TODO item 9.

* The seam
# what the adapter talks to, in one paragraph.
  OpenCode's own headless server, on the loopback: =opencode serve=
  prints the address and a fresh password when it starts, and the
  adapter reaches it over plain HTTP. The password and the address come
  from the environment (=AIU_AGENT_URL=, =AIU_AGENT_USER=,
  =AIU_AGENT_PASSWORD=, =AIU_AGENT_DIRECTORY=) because they are facts
  about this run, not a config file to load at startup (rule 03).

* What the server gives, in its own words
# the calls this program uses, and the shape of each answer.
  - =POST /api/session= opens a session and answers ={data:{id:…}}=.
    The session may carry a PERMISSION RULESET, and that is the gate:
    the editor opens every session with =edit=, =bash= and =webfetch= at
    =ask=, so the agent's writes come back as permission asks.
  - =POST /api/session/{id}/prompt= hands the bundle over and answers
    at once; the reply arrives on the event feed, not in the answer.
  - =GET /api/event= is the event feed: a stream of =data: {…}= lines
    with a =type= and a =data=. The turn ends at
    =session.execution.succeeded=, and a permission arrives as
    =permission.asked=.
  - =GET /api/session/{id}/permission= lists the pending asks, each
    with its id, its action and the files it touches.
  - =POST /api/session/{id}/permission/{id}/reply= answers one ask:
    =once=, =always= or =reject=. The approval is never inferred.
  - =POST /api/session/{id}/interrupt= cancels the turn, and
    =DELETE /api/session/{id}= ends the session.
  - =GET /api/info= answers the version, so the pin is the version that
    is really there (=2.1.0= on this phone) and not one this program
    remembers.

* The three findings that cost time
# the things the next adapter should not rediscover.
  - **The feed is CHUNKED.** The event stream arrives with
    =transfer-encoding: chunked=, and the framing is inside the bytes
    the reader sees: a size line, the text, a blank line. A reader that
    takes the lines as they come reads the framing as text and misses
    the events that straddle a chunk. The client in =machine/http.rkt=
    takes the framing off first.
  - **The feed must be open BEFORE the bundle goes out.** An event that
    came before the feed was open is an event nobody saw: the
    permission ask was missed exactly this way, and the editor waited
    for a turn that was already waiting for a human.
  - **This Racket has no http collection of its own.** There is no
    =racket/base64= either, and no =string-index=: the client uses
    =net/url=, =racket/tcp=, =net/base64= and the slimmed
    =racket/string= that this build has. =string->number= with a radix
    of 0 is not allowed: the radix is 2 to 16.

* What the round trip cost on the phone
# the honest numbers.
  - The bundle out, the answer back, with the events between them: about
    5 to 20 seconds, and the wait is the model's, not the program's.
  - The editor's own work: the start is 130 to 220 ms, and the HTTP
    calls are milliseconds.
  - The agent's write stayed gated until the human answered, and the
    file landed only then.

* What was decided because of it
# the choices the test forced.
  - One session per project, steered by the bundle's selection, and NOT
    a session per send: a session per send throws the conversation away
    and resets the =always= answers.
  - The session is opened with the mutating actions at =ask=. Without
    that, the agent's write lands with nobody asked.
  - The pins come from the server, so the version recorded is the
    version that answered.

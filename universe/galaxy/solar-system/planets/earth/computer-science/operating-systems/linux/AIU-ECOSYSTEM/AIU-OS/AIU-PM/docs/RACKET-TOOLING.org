* What is installed
Racket 9.3 CS FULL lives in =~/opt/racket-full=, installed 2026-10-15 with
the official .sh installer; DECISIONS.org D-042 records the version and the
installer SHA. =rackunit-lib= is the only package added on top.

| package | status | why |
|---------+--------+-----|
| =racket-lib= | bundled | the language and collections |
| =rackunit-lib= | installed | the test framework every test file uses |

=data-lib= was installed and then REMOVED. It does not ship =data/list=
in this version, so it delivered nothing, and it cost startup:
=racket -n -e ''= went from 0.299s to 1.178s. Back to baseline after
removal.

* What is already there, no install needed
Measured on this phone, not assumed:

- =json= WORKS. =(require json)= loads from the bundled collects and
  =(jsexpr->string (hasheq 'a 1))= prints ={"a":1}=. The engine's step
  journal (E-10) is JSON Lines, so this is the important one and it cost
  nothing. =raco pkg install json= fails with "cannot find package on
  catalogs" precisely because it is already there.
- =read-line-evt=, =wrap-evt=, =eof-evt= are in =racket/port=. Valid line
  modes are exactly ='(linefeed return return-linefeed any any-one)= (see
  =collects/racket/port.rkt:252=). ='line= does NOT exist.
- =exit-handler= and =environment-variables-copy= are in =racket/base=.
  =current-exit-handler= is NOT exported by the =racket/base= language.
- =racket/contract= and =racket/cmdline= are both present.

* What the full distribution changed
This section said minimal lacked =racket/glob=, =racket/environment= and
=directory-list-recursively=, and warned code not to assume them. The full
distribution is installed now (2026-10-15, D-042); verified on it
2026-10-16:
- Globbing: =file/glob= loads and =glob= works (the old note's
  =racket/glob= is not a module in 9.3; =file/glob= is the real name).
- Environment variables: =environment-variables-ref= and
  =environment-variables-set!= are in =racket/base=; there is no
  =racket/environment= module in 9.3.
- Directory walks: =directory-list= and =in-directory= work in
  =racket/file=; =directory-list-recursively= and =directory-list*= do
  not exist in 9.3.
Passing file lists to programs as arguments is still fine; it is no longer
a necessity.

Packages tried and NOT in the catalog (network was up, HTTP 200, so this
is genuinely "not published there"): =lsp=, =raco-test=, =typed-json=,
=json-lib=. Each resolved against four catalog URLs and then reported
"cannot find package on catalogs".

* Scripts and what they are for
House rules for using them live in =AGENT.md= at the repo root.

| script | job |
|--------|-----|
| =check.nu= | the gate; =--fast=, =--changed=, no flag = full |
| =test-runner.rkt= | one process, many submodules; prints TEST-START/END, SLOWEST, SUMMARY |
| =read-check.rkt= | reads named .rkt files, reports READ-BAD with file and line; the paren check |
| =repl.rkt= | loads the core modules once then evaluates stdin expressions |
| =env.nu= | XDG roots, =CARGO_TARGET_DIR=, cargo on PATH |
| =tree.nu= | tree view excluding compiled, target and .git |
| =need-nu.nu= | reports the pinned Nu, fails clearly on mismatch, never fetches |

* REPL measured, honestly
Five trivial probes, the same work either way:

| how | real time |
|-----|-----------|
| 5 expressions through one =repl.rkt= | 11.778s |
| 5 separate =racket -n -e '(void)= launches | 1.531s |

For trivial work the separate launches win: the REPL pays a heavy one-off
cost loading 13 core modules. The REPL wins when expressions are not
trivial, and above all when an expression RAISES and the stack stays
alive for the next probe. Use it for investigation, not for one-liners.

* Startup cost, measured
=racket -n -e ''= varies between 0.29s and 1.12s for the same empty
program on this phone. That spread is filesystem variance under proot,
not compute, and every separate process pays it. That is the reason
=test-runner.rkt= runs files in one shared process.

* How packages get installed here
=#~/opt/racket-full/bin/raco pkg install NAME=, always with
=GIT_TERMINAL_PROMPT=0= so a network problem fails fast instead of
waiting for a prompt. No timers, no polling (D-015).

#+TITLE: Secrets handling
# One job: how the secrets package stands between the agents and any token or password
# Status: filled 2026-10-16; recommendations await owner review.

* The questions
# the questions this file must answer, listed before any option is weighed.
  - Rule 07 in the three programs says agents never receive tokens or
    passwords and points at "the existing secrets-for-AI package" — which
    package, and until it is found, what stands in its place?
  - Where is the single seam that injects a secret on the program's
    behalf, so no agent context, environment, file or transcript ever
    holds one?
  - What happens the day sops and age arrive — the owner's named
    direction?

* Options
# two or three real options, each with what it costs and what it gives.
  - Option A — wait for the package to be located; meanwhile enforce "no
    credentials to agents" by policy alone. Cost: no convenience exists
    for the case that needs a secret at all, and the rule leans on
    discipline until a gate can bite. Gain: nothing invented, nothing to
    unbuild.
  - Option B — an interim seam: one redaction path upstream of every
    destination — the screen line, the log, the feed, the transcript —
    plus a wrapper that injects secrets into the program's own
    environment, never the agent's. Cost: a second thing to replace when
    the package lands. Gain: the promise holds mechanically today, and the
    package later slots into the same seam without moving it.
  - Option C — scoped tokens handed to agents through their environment.
    Cost: violates rule 07 outright; tokens leak into transcripts and
    third-party context. Gain: convenience; refused by name.

* Recommendation
# one recommendation, named plainly, with its reason.
  B, with A's floor: no secret ever crosses into an agent's reach, and the
  redaction seam plus injection wrapper are the openly temporary parts.
  When the secrets package lands — sops + age, per the owner — it takes
  the same seam and the wrapper is deleted. Until then the enforcing shape
  is the one already proven: policy predicates that refuse with the rule's
  name (agents/policy.md), applied where a credential could enter, which
  is exactly what rule 07 demands.

* What it needs from the package manager
# anything this design needs from PM, marked for the later PM prompt.
  - PM is where the first real need lives — fetch and install paths carry
    credentials. Identify and integrate the package there first; the
    checklist item lands in pm-change-checklist.org.

* Open decisions
# what remains undecided and who decides it.
  - The package's identity: not located 2026-10-16 (searched by name on
    the web, GitHub, npm, pypi, and by grep in-tree) — owner.
  - The injection shape — wrapper, proxy, library — and where it runs:
    unanswerable until the package is identified — owner, later.

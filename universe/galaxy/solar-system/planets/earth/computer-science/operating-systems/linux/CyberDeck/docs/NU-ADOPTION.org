#+TITLE: Nushell adoption design (D-020, for approval)
#+AUTHOR: Shape

Evidence: docs/NU-NOTES.org. Pinned ~/opt/nushell/0.116.1/nu, always
with --no-config-file. check.sh stays the gate until check.nu is proven.

* a. Scope
Nu owns scripts/ (check, startup, env, lib-obs, wrappers, lints) and
all new tooling. No version is pinned: scripts/need-nu.sh reports
which binary they would use (newest ~/opt/nushell/*/nu, else PATH)
and its version, and fails clearly when none exists. Versions change
only by hand; nothing ever downloads or updates Nu automatically.
POSIX sh stays ONLY for: the fixed fragments embedded in
backends/run.rkt (fd redirection, traps, flock, exec on a bare
machine where no Nu exists) plus scripts/need-nu.sh itself.
The package manager core stays Racket. Rationale: run.rkt fragments
execute inside spawned children that cannot depend on ~/opt; everything
else benefits from structured data and fail-fast externals.

* b. JSON bridge: --format sexp|json on every pm command
Default sexp (today's output, unchanged). --format json prints the same
data as JSON: same fields, same order, same error shape (who/message/
fields/hint become keys). Schema per command is documented in
docs/ERRORS.org beside the E-15 table as commands land (check first).
Conformance test: for each command, parse both outputs and diff the
data (sexp read vs json parse must be equal modulo key order). The TUI
snapshot producer and Nu scripts consume only the JSON side.

* c. Event log format: JSON Lines (DECIDED)
Today: observability is queued (STEP 6a), no log exists yet. JSON Lines
wins: Nu reads/writes it natively (open, to json, append); the Rust TUI
parses it without an s-expression parser; Racket reads it with the json
library. Specs, lockfile and manifest stay .rktd.
Rules (all test-pinned at implementation):
1. One JSON object per line, UTF-8, never rewritten. Every record
   carries format-version, run id, event type, a UTC timestamp (ISO
   8601 string) and, for end events, the monotonic duration as an
   INTEGER number of nanoseconds (no floats). Readers ignore unknown
   fields, so the schema can grow.
2. Fixed conventions: symbols and paths as strings; booleans as
   true/false; absent as null. A record never embeds large output:
   full stdout/stderr go to separate raw files, and the record holds
   the path, byte counts and the tail.
3. Concurrent writers: one log file PER RUN (named by run id), so a
   worker and a CLI never interleave lines, plus an index file written
   with atomic append of short lines (one line per run: run id, op,
   outcome). pm log list reads the index, then the per-run files.
4. Redaction stays visible: redacted fields read «redacted:KEY».
   Redaction runs before anything is written, never after.
5. One Racket module defines the record schema and writes lines; one Nu
   helper writes the SAME records for scripts. A conformance test
   parses a Nu-written and a Racket-written record with BOTH languages
   (mirrors the --format sexp|json parity rule).
6. The screen is rendered FROM these records, so screen and log can
   never disagree: same data, two renderers.

* d. Lint: O-9 hidden-discard gate learns Nu
Banned patterns under the same OBS-OK: reason rule: =| ignore=, =do -i=
/ =do --ignore-errors=, bare =try= without catch, redirects to
/dev/null or =null=, and unchecked =$in.exit_code= after =complete=.
Ban =sleep= and every timeout/timeout-at in Nu too (D-015: waits end on
process exit, EOF, lock release, explicit cancel). check.sh gains the
grep gate now (it applies to .nu from the first Nu script); check.nu
inherits it.

* e. Migration, one script per commit
New scripts are Nu from now on. Existing scripts (check.sh,
startup.sh) convert during the end-of-stage items, one per commit, each
with a parity proof: run the sh and nu versions against a clean tree
(green both) and a deliberately broken tree (same failure, same exit
code), paste both outputs in the commit message. check.sh retires only
after check.nu passes parity plus a full green gate.

* f. Bootstrap on a fresh clone
The pm cannot build Nu (cargo fetches outside git, D-019), and nothing
fetches it automatically either. A fresh clone gets it by hand (any
recent stable aarch64 build); scripts/need-nu.sh reports which binary
and version is in effect. No system install, no PATH surgery, no sudo.
Vendor nothing (Nu binaries stay out of git).

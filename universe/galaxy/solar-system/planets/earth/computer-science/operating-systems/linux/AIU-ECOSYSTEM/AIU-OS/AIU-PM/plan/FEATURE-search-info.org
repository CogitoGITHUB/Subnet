#+TITLE: FEATURE search-info — browse declared packages, show one
#+AUTHOR: Shape

Design only. No code lands with this file.

* Goal
Two read-only queries. =pm search= browses what is declared; =pm info= shows
one package in full — version, source, dependencies, owner, holds — so
nobody has to read a profile tree by hand to answer a question pm can.

* Command shape and operands
=pm search PATTERN= — the operands are the pattern; it matches name and
summary, case-insensitively. Read-only.
=pm info NAME= — one operand, the package name. Read-only.
Reads: the declaration directories, the manifest, the profile ownership
map, and the holds file.
Writes: nothing.

* Area
=entry/search-report.rkt= and =entry/info-report.rkt= — read-only report
documents over spec, store and install. entry is the only area that may see
all three at once under the one-way law.

* Refusals
- info refuses an unknown package, naming it and the directories searched.
- search with no match is NOT an error: it prints nothing and exits 0. An
  empty result is an answer, not a fault.
- Neither command has =--confirm=; neither writes.

* Narration
- STEP "scan" naming the directories searched and the pattern.
- SKIP a declaration that will not parse, naming the file, and keep going.
- END with the match count.

* JSON output keys (fixed order)
Search: =name=, =format=, =operands=, =matches=, =count=, =pattern=. Each
match is {name, version, summary} in that order.
Info: =name=, =format=, =operands=, =package=, =version=, =source=,
=dependencies=, =owner=, =holds=, =dev=.

* Open questions
- Should search also cover names fetched into the vault, or only declared
  packages?
- Does info show the lock pin, or only the declared source?

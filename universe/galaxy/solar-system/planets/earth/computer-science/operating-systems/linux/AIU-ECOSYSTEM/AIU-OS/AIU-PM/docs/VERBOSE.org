*** How package-manager/src/entry/cli.rkt builds command->json

Three small pure functions, no printing:

1. =command->datum= (line 179) -> =(list NAME FORMAT OPERANDS...)=,
   one =cond= arm per command struct.
2. =command-envelope= -> the string ={"name":...,"format":...,"operands":[...]=
   with NO closing brace, so a command can append result keys.
3. =command->json= -> the envelope plus =}=.
4. =run-command-json= -> the envelope plus =,"packages":...= or
   =,"ok":...=, as a STRING, because write-json would reorder the keys
   and the documented order is ours.

V-3 routes the printing of 4, not the building: =run-command-json= is
already a pure string and stays pure.

** The V-1 module
*** Event fields
=run-id=, =seq=, =parent-id=, =kind=, =who=, =what=, =why=, =how=,
=inputs=, =outputs=, =result=, =utc=, =mono-ms=, =duration-ms=.

=kind= is one of START STEP INFO DECIDE SKIP PROGRESS END FAIL WARN.

*** Why is mandatory
=step=, =decide=, =skip= and a failing =with-op= all REQUIRE =why=.
A missing or empty =why= raises. There is no default reason and no
silent skip.

*** Destinations
One event, three places: the screen line, =<state>/events/<run-id>.jsonl=,
and the =<state>/events/current= pointer to the active run id. The AI
reads the same JSON Lines file; there is no second format and no
polling. The package manager never waits for a reader.

*** Screen line
=[HH:MM:SS.sssZ +0.250s] START fetch pkg-alpha | what: ... | why: ... | how: ...=
indented two spaces per nesting level, flushed after every event.

*** Redaction
Every field goes through =trace-redact= (package-manager/src/narration/event-text.rkt:84) before ANY
destination, so a password cannot reach the screen, the log or the
feed by three different routes.

* 5. The exact gap — why this is not three one-liners

=profile-activate= and =profile-remove= both take an ENTRIES list:

    (listof (list name:string? source:path-string? rels:(listof string?)))

That is: for each package, its name, the directory it was installed into,
and the list of RELATIVE paths it installed (e.g. ='("bin/prog")=).

**No production code in the tree builds this list.** It appears only as
hand-written literals in two tests:

    ; backends/query.rkt:428
    (profile-activate (list (list "pkg-a" (path->string store-a)
                                  '("bin/prog")))
                      (path->string prof3))

    ; backends/dev.rkt:286
    (profile-activate (list (list "pkg-e2e" ver2 ...)) ...)

So the real work is an entries builder: read a declaration, find where
each package is installed, and collect its relative paths. Build it
once, in one place, and have all three commands use it.

Where the data comes from:
- name + version: =core/lock.rkt=, =lock-entry-name= / =lock-entry-version=
- installed-at path: the store dir. See =core/plan.rkt=,
  =package-plan-store-dir= (it is =<state>/store/<name>/<slot>/<version>-<hash12>/=)
- rels: the =install= form of each spec, read by =read-install= in
  =core/spec-read.rkt=; the same relative paths =check-spec-conflicts=
  and =spec-install-dests= in =core/plan.rkt= already walk. Reuse that
  walk; do not write a second one.

Note the shape mismatch to bridge: a =lock-entry= has
=(name version commit url slot flags spec-hash input-hash deps)= and NO
relative-paths field. The rels live in the SPEC's install form, not the
lock. That is why a lock alone is not enough to build entries.

* 7. Hard rules — each one has a story

- **Every command can emit JSON** with a fixed key order:
  ={"name":...,"format":...,"operands":[...], ...results}=. All five
  surfaces (CLI, MCP, skill, plugin, television) read this one shape.
- **docs/API.org is a TEST, not prose.** =cli/main.rkt= parses and
  executes every example in it. If you change a command's operands you
  MUST update API.org or the suite fails. It caught four wrong examples
  in one session, all hand-written, all wrong.
- **Every command text is emitted through one printer.** Never
  =printf=/=display=/=eprintf= to console; stage 14 of the gate fails the
  build. Use =display-result=.
- **Effects are allowlisted.** =scripts/check.nu= stage 15 has a named
  list of file writers and process spawners. Adding a new one fails the
  gate. You should not need to add any.
- **Narration is mandatory.** Use the verbs in =core/verbose.rkt=:
    (with-op who what why [thunk])      ; START/END, FAIL on error
    (step who what why #:how h)         ; a step
    (wait-for who what why #:how h [thunk])  ; WAIT before a block
    (decide who what why #:chosen c #:alternatives (list ...))
    (skip who what why)  (warn who what)  (note who what)
    (progress who what #:done d #:total t)
  =why= is never optional; a blank one raises. There is no off-switch and
  none may be added. =wait-for= exists because a block that did not
  announce itself cost a 41-minute hang; use it on anything that can
  block.
- **Refusals name their rule** and exit non-zero. A refusal is not an
  error envelope — errors are exit codes, because only the exit code
  honestly distinguishes "no results" from "refused".
- **Doc line limit 102** or stage 6 fails.

* 8. Traps that have already cost real time here

- **A narration wrapper keeps only the FIRST of a thunk's values.**
  =(with-op ...)= and =(wait-for ...)= both do. If you need several
  values out, have the thunk return a LIST, or stash them in a box.
  Returning two values and destructuring after silently loses the second.
  This caused two separate multi-hour debugging sessions.
- **Stale bytecode lies.** After a contract change, run =$RACO make= on
  the file before trusting a test result. A bizarre contract error right
  after an edit is the cache, not your code.
- **=read-check.rkt= now names the unclosed form.** If it fails it prints
    READ-UNCLOSED <file> '(' opened at line N: <the text>
  Trust that line. Do NOT go counting parens elsewhere, and do not
  "fix" a line it did not name — an earlier session burned hours editing
  correct lines while a =(define (as-dir d)= with its body deleted
  elsewhere was the actual fault.
- **=current-allow-file-urls= is a PARAMETER**, not a procedure. Fixtures
  use =file://=, so any spec/lock/manifest/vault read in tests stays
  wrapped in =(parameterize ([current-allow-file-urls #t]) ...)=.

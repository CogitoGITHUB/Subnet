#+TITLE: Errors
#+AUTHOR: Shape

Kinds live in =package-manager/src/errors/error-type.rkt= (E-3): =spec resolve fetch verify build
install config internal=. One struct =exn:fail:pm= with =kind=, =fields=,
=hint=, =cause=. Raise only through =raise-pm-error= (E-4). Catch
narrowly (E-5). User errors print clean messages; internal errors print
full context plus a bug banner (E-7).

Message shape (E-1, E-2): =who: message;= then =  field: value= lines,
then =  hint:=. Every error answers WHAT, WHERE, WHY, NEXT.

* Exit codes (frozen table, D-045)

| Code | Meaning                      |
|------+------------------------------|
|    0 | success                      |
|    3 | spec invalid                 |
|    4 | resolve (deps)               |
|    5 | fetch (network)              |
|    6 | verify (hash)                |
|    7 | build failed                 |
|    8 | install failed               |
|    9 | activate (conflict)          |
|   70 | internal bug (EX_SOFTWARE)   |
|   78 | config (bad CLI or config)   |
|  130 | interrupted (Ctrl-C)         |

The two sysexits rows carry their outside names on purpose: 78 is
EX_CONFIG and 70 is EX_SOFTWARE, so a reader does not have to look
them up. Code 2 is gone with the last invented number -- a bad
command line raises kind =config=, which is 78.

Samples will be collected here as error paths are implemented (E-12).

* Samples (from =core/*= tests, exact output)

test-pinned when activation lands in STEP 5, exit 9, nothing changed):

activate: file conflict, nothing changed;
  file: bin/bats
  owned-by: bats-core 1.14.0
  claimed-by: pkg-foo 2.0
  hint: deactivate one package or pass --override 'bin/bats' PKG
#+end_example

#+TITLE: Rebuilt client and running holder
# One job: what happens when a rebuilt client meets a holder that still runs the old contract
# Status: filled 2026-10-16; working draft until a program and an adapter both depend on it.

* What this freezes
# the exact thing every program and adapter must obey; if it is not frozen here, authors guess.
  The meeting rule: the holder outlives clients (rules 01 and 03). A
  rebuilt client exchanges contract versions with the holder at attach;
  agreement attaches; a mismatch refuses by name, showing both versions
  and the safe path. Nothing is lost; sessions keep running through the
  mismatch.

* Shape
# names and meanings only: the fields and what they promise. No code, no examples.
  - At attach: versions exchanged before anything else; a mismatch
    refusal names both versions and the safe path — finish the session
    and restart the holder, or run the old client.
  - The holder does not negotiate, migrate or upgrade itself; it holds
    terminals and the log (rule 03).
  - Layout and log files stay readable across the mismatch, or refuse by
    name — never silently rewritten.
  - The client never auto-downgrades to guess a match; it names the
    command instead.

* Who obeys it
# every program and adapter this applies to, named.
  The multiplexer's holder and its clients; any long-running holder the
  ecosystem grows later.

* How it changes
# how this can change without breaking a running client; point at a D-number once one exists.
  The rule itself changes only with the contract version; new refusal
  paths are additive. Freeze condition: a program and an adapter both
  depend on it; none yet.

* Open decisions
# options with a recommendation, or none yet.
  - A compatible mode when a matching older client exists —
    recommendation: the client names the old client and refuses to
    guess; no automatic mode.

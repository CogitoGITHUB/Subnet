  - Television is the external picker harness; PM ships channels for it, not a UI.
  - The facts here are taken from PM's own decision D-039 and its agent/tv tree.

** Television is the UI, and it lives outside PM
# A deleted in-project TUI was replaced by channels, not by new PM code.
- What PM does: the Rust TUI was deleted; its replacement is television channels, because PM already emits everything a browser needs — one-line JSON documents per command and the JSONL event feed (D-039).
- The rule: the tool that produces state exposes it as data, and the picker that browses that data is a separate, replaceable program.
- Verdict: REUSE.
- Read at: plan/DECISIONS.org D-039; plan/DECISIONS.org D-035 (the deletion).

** Channels are read-only over PM's JSON, and never implement PM logic
# Every line on screen comes from PM's own output, reshaped.
- What PM does: tv reads PM's JSON through Nushell source commands (shell set to nu) and hands selections back as values; it never implements package-manager logic; all browsing is read-only by construction (D-039).
- The rule: the UI layer holds no rules of its own, so it can never disagree with the engine.
- Verdict: REUSE.
- Read at: plan/DECISIONS.org D-039; agent/tv/README.org.

** No one-keypress apply: state changes hand off to the human flow
# The only mutating actions leave the picker and enter PM's confirmation path.
- What PM does: the only state-changing actions are execute-mode handoffs into Nu scripts that run PM's own human confirmation flow; there is deliberately no one-keypress apply (D-039).
- The rule: a picker may select, never execute; mutation keeps its existing gate.
- Verdict: REUSE.
- Read at: plan/DECISIONS.org D-039.

** Channels live in the repo and install by a print-only script
# The same pattern as the OpenCode plugin: show the commands, write nothing.
- What PM does: channel sources live in-repo under agent/tv/ and install by symlink into television's cable directory through a script that only prints the commands — a script that silently edits a config directory is exactly the surprise this project does not do; the tv side is opt-in (D-039).
- The rule: installation instructions you can read beat installation side effects you cannot.
- Verdict: REUSE.
- Read at: tools/install-tv-channels.nu header; plan/DECISIONS.org D-039.

** The channel environment contract
# One required root variable; nothing runs without it; optional vars have defaults.
- What PM does: PM_ROOT is required — channels invoke the CLI from it and nothing runs without it; PM_SPECS is optional with a default; PM_PROFILE and PM_LOCK are required by the packages channel; all commands run under the nu shell.
- The rule: the picker is pointed at a checkout by one variable, and every other boundary is explicit.
- Verdict: ADAPT — each new program would ship its own channels over its own JSON surface, with its own one required root variable and explicit optional ones.
- Read at: agent/tv/README.org.

** The two example channels, as shapes
# Specs get one validating line each; packages get one held-marked line each.
- What PM does: the specs channel lists one line per spec file, previews cycling file contents and the check verdict, and offers one validating action; the packages channel lists one installed package per line with held marks and previews state from the profile and lockfile.
- The rule: a channel is a read view over one command's JSON plus previews and at most one action.
- Verdict: ADAPT — the shapes are the lesson; the channels themselves are PM-specific and the new programs should design their own.
- Read at: agent/tv/README.org.

** Prerequisites are pinned like everything else
# Television itself arrives through PM, from a pinned spec.
- What PM does: television is installed by PM from a spec example pinned to a version (v0.4.21 at the time of reading); shell integration is a one-time human step; the cable directory defaults under the television config dir.
- The rule: even the tool that browses the tool is pinned and recorded, never assumed present.
- Verdict: REUSE.
- Read at: tools/install-tv-channels.nu; docs/examples (the tv spec example).

** One JSON shape, five readers
# CLI, MCP, skill, plugin and television all read the same documents.
- What PM does: the JSON documents and the event feed are the single surface; the handoff notes that CLI, MCP, skill, plugin and television read one shape.
- The rule: surfaces multiply; the shape does not — every new consumer is an argument for keeping the surface boring.
- Verdict: REUSE.
- Read at: docs/HANDOFF-PROFILE-COMMANDS.org section on surfaces; docs/API.org.

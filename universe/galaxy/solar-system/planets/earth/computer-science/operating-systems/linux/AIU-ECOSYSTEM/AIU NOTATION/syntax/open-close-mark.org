#+TITLE: The open and close mark
# One job: the tiny consistent mark around a named element — the sign is decided: braces { }
# Status: the sign decided 2026-10-17 by the owner (notation D-014); the parser side starts at TODO item 2.

* What it is for
# why this exists, in the owner's terms. The mark exists so a name can be opened and closed without one symbol per element.
  - Ordinary things are written as names, not as symbols; the same pair of marks
    opens and closes every named element, so nothing new must be remembered per
    element (rule 12).

* The shape
# how it reads, in words; no code here, the implementation is TODO item 2.
  - { opens a named element and } closes it; one pair for every element kind.
  - The body between them is ordinary text; the element's name is written inside,
    in words: title, paragraph, code block.
  - A code block's body is opaque to the parser: the parser does not read code as
    notation text, so a { inside code never opens a notation element.
  - A code block closes by repeating its own word: the word that opened it stands
    again, alone, on its own line, and that line is the closer (owner, 2026-10-17 —
    the named closer, not a brace).
  - The hole fix: a word closes a code block only when it stands alone on its own
    line and matches its own opener; the same word sitting inside a line of prose
    or inside code is ordinary text, never a closer.
  - The editor hides the closer when it shows the file; the file itself keeps it.
  - Whether ordinary elements (title, paragraph) close the same way is still open
    and is not decided here.
  - A { in ordinary prose still opens an element; the first elements and the
    typing-comfort check inside TODO item 2 decide how that reads for the owner.

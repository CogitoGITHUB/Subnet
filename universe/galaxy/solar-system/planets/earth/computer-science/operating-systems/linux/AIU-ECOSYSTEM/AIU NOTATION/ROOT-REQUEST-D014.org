** 2026-10-17 D-014: the mark — elements named in words, opened and closed by start/end keywords, everything inside a block
   Touches AIU NOTATION/TODO.org; AIU NOTATION/HANDOFF.org; AIU NOTATION/questions/usage-inventory.org; AIU NOTATION/syntax/open-close-mark.org.
1. WHAT: elements are written as names, not per-element symbols (title, paragraph, code block — the owner's words); a block is opened by "<name> start" and closed by "<name> end", each alone on its own line, the same name in both; no braces. Everything lives inside a named block, paragraphs included, so there is no default paragraph and blank lines between blocks carry no meaning. Text outside any block is an error named "stray text" — severity error, no off switch — kept untouched, never deleted or rewritten, while the rest of the file keeps parsing; the meaning tree holds blocks and error nodes only. Blocks nest, and a closing line that does not match the innermost open block is a precise error naming the opener's line. A code block's body is opaque: only an exact matching end line closes it. Styling is declared on keyword-colon lines under the start line and stored as hints, never as meaning. Revised the same day; the first answer was braces { }.
2. WHY: the owner answered 2026-10-17 and revised it the same day on the phone. The names-not-signs line became the law, and the sign became two words in the language itself — the same shape a reader already uses to open and close things. Making every element a block removes the question of what a loose line means, so the parser has one rule instead of two, and the engine can refuse stray text with no off switch. Opaque code bodies make one closing rule safe for prose and code alike.
#+end_example

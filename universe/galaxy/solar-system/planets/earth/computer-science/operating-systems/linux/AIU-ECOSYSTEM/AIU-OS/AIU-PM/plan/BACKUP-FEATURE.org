#+TITLE: BACKUP — cloud backup of declarations and fetched sources
#+AUTHOR: Shape

* What it is
When =pm= fetches a package, copy both the declaration and the fetched
source into one dedicated git repository, the backup repo, then push
that repository to a configured cloud remote.

| what | where in the backup repo | shape |
|------|-------------------------|-------|
| the declaration | =decl/<name>.spec= | exact copy |
| the package source | =vendor/<name>/= | plain snapshot, NO =.git=, NOT a submodule |

Backup is exactly that: a BACKUP. It is never an input to install, never a source
of truth, and a backup failure must never fail the fetch that preceded
it.

* Where the code lives
All backup logic in =src/backup/=, with tests in =tests/backup/=.
Every git call goes through the =git/= area. The backup area must not
edit =git/, =process=, =spec= or =apply=.

* Configuration
Two settings, read from wherever =pm= already reads its other state:
the local path of the backup repo, and the remote URL to push to.
Not configured is NOT an error: the run is SKIPPED and says so with a
skip narration naming the rule.

Automatic backup on fetch happens only when configured. =pm backup
SPECDIR= works without any configuration beyond the backup path.

* When it runs
After a fetch that SUCCEEDED, once per fetch batch. Every new
declaration and source in that batch is copied, committed as ONE commit
naming the packages and versions, then pushed.

* Invariants
- **Idempotent.** Unchanged files produce no commit. Running twice
  changes nothing the second time.
- **A push failure never fails the fetch.** Warn, record pending state,
  and exit as the fetch would have. The next backup run retries the
  push FIRST, before copying anything new.
- **Push is wrapped in the wait door** (=wait-for=), because it blocks.
- **Push to the configured remote only.** Never force-push. Never
  rewrite history.
- **Secrets are never copied.** A file named =.env=, =*.key=, =id_*=
  or =*.pem= is skipped with a warn naming the file and the rule.
- **Size limit.** A source snapshot over the limit (default 50 MB,
  configurable) skips that PACKAGE with a warn and still copies its
  declaration. One big package must not cost you the whole backup.

* The command
=pm backup SPECDIR=
- without =--confirm=: prints exactly what WOULD be copied, committed
  and pushed, and changes nothing.
- with =--confirm=: does it.
- JSON always carries ="confirmed"= and ="applied"=, like every other
  mutating command.
- It also BACKFILLS packages fetched before this feature existed.

* Build order
1. Copy and commit logic, tested on a temp git repo holding a real
   two-package declaration. No push. Test idempotence and secret-skip
   here.
2. Push and retry, tested against a local BARE repo. An unreachable
   remote must never fail the caller.
3. The =pm backup= command, with an =API.org= example matching real
   output. =API.org= executes, so a stale example fails the suite.
4. Hook into fetch. Update fetch's =API.org= example only if its output
   actually changes.
5. MCP entries last; update the stale MCP tests.

* Gate
The backup work (the naming law is =banned-words-lint=, the one-way
dependency is =one-way-dependency-lint=) carries a named, justified
allowlist for the backup files only. Entries name a file and say why,
never a bare count.

* Open questions
- Where exactly does the backup path come from: a new XDG config root,
  or a sibling of the vault? The vault is the existing git-owned
  location, so a sibling of it is the obvious default, but this is a
  decision for the owner rather than an assumption.
- Should a push retry block the caller or run detached? D-015 forbids
  timers, and a detached push needs somewhere to record its result.

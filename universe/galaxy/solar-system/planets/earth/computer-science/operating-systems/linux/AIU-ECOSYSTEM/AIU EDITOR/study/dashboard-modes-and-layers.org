#+TITLE: Dashboard modes and layers
# One job: every dashboard mode and layer, and how they interact
# Status: filled 2026-10-16 from Cyberdeck-Emacs, read-only; not yet reviewed.

* Modes and layers
# every mode and layer the dashboard defines, one line each: what it captures and what it passes on.
  - dashboard-mode — the major mode of the dashboard buffer: read-only,
    special, undo and line numbers off, page breaks on, refresh on revert.
  - The vendored engine — the upstream insertion, navigation and item
    machinery that dashboard-mode runs on.
  - Sections — the visible stack of item sections in order-file order; each
    section is produced by one widget.
  - The banner — a drawn layer at the top of the buffer, recomputed per
    width; structural, always first, never part of the order file.
  - Desk faces — the mono overlay for banner, headings, items and footer.
  - The desk mode hook — strips the model line from the dashboard buffer,
    centers content with olivetti, and adds the desk's own jump keys.
  - The status widget's live layer — rewrites its own lines on a timer
    without re-rendering the rest of the desk.
  - mini-modeline — the bar as a minibuffer surface, two stacked rows,
    hiding the real mode line wherever it runs.
  - Modeline rows — row 1 identity (keyboard state, modified, buffer name,
    position; right: branch, cyberdeck letters); row 2 context (left: doctor;
    right: datetime).
  - Modeline segments — the zero-argument render functions the rows are
    composed from.
  - The optional header row — a separate window line at the top of a window,
    off by default; not a second modeline row.
  - The fuzzy clock — vendored words source used by the datetime segment,
    with its own mode left off.

* How they interact
# the rules that decide which layer sees a key or event first.
  - Open order: banner first (always), then sections in order-file order,
    then the footer; the bar installs separately at after-init.
  - Key priority in the dashboard buffer: the desk's jump keys sit in the
    mode hook's local map, the vendored engine's navigation keys in the mode
    map; the buffer is read-only, so nothing edits.
  - The order file decides what shows and in what order; the registry decides
    section length; stock sections appear only when the order file lists
    them, while registry widgets append even when unlisted.
  - The bar composes left and right as exactly two lines each; empty rows
    render blank so the pairing holds; a sick segment shows "?" and never
    breaks the row.
  - Refresh rules: full redraws are throttled and erase first (resize, save);
    the status section rewrites in place; the bar pushes on state change and
    on its own timers.
  - Model line ownership: the desk buffer shows no model line, the bar lives
    in the minibuffer, and the optional header conflicts with olivetti, which
    is why it is off by default.

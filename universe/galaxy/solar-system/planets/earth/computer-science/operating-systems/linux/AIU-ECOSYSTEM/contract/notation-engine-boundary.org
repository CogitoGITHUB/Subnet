#+TITLE: Notation engine boundary
# One job: the LSP-like surface through which the editor and the multiplexer reach the notation
# Status: filled 2026-10-16; working draft until a program and an adapter both depend on it.

* What this freezes
# the exact thing every program and adapter must obey; if it is not frozen here, authors guess.
  The notation side: an LSP-like surface the editor — and the
  multiplexer, where it shows notation — calls; the notation never calls
  back into them; the editor's loader never depends on the notation
  (rule 14).

* Shape
# names and meanings only: the fields and what they promise. No code, no examples.
  - Calls: open a document; apply an incremental change; report the new
    parse and its errors; render views; resolve a node address; literate
    operations — load a chunk, send a chunk to a target, scan
    dependencies; propose completions for names; trigger the engine
    build.
  - LSP-like, not LSP-the-letter: the same shape of ideas, sized to this
    notation.
  - Absence rule: with the notation absent every program still starts;
    the editor can trigger the engine build and enters dev mode after it
    finishes (rule 14).
  - Versioned: an engine and an editor that disagree refuse each other by
    version, by name.

* Who obeys it
# every program and adapter this applies to, named.
  The notation implements it; the editor consumes it; the multiplexer
  consumes it where it renders or sends notation. A send's node address
  crosses here (see node-addressing-and-comments.org).

* How it changes
# how this can change without breaking a running client; point at a D-number once one exists.
  Methods are additive; a stale engine is refused by name. Freeze
  condition: a program and an adapter both depend on it; none yet.

* Open decisions
# options with a recommendation, or none yet.
  - How literally the LSP shapes are followed — recommendation:
    LSP-like only; the notation's needs lead.
  - Transport — recommendation: stdio first; a socket only if the phone
    proves a need.

#+TITLE: adapter versioning and rollback — refuse a stale adapter by name
#+AUTHOR: Shape
# One job: agent adapters as PM packages with two version pins, one
# versioned contract, and rollback like any generation. Status: planned
# only; nothing here is built. Source:
# =../../pm-integration/adapter-versioning-and-rollback.org=.

* Purpose
- The agent adapters (OpenCode, Hermes) become installable PM packages
  with the promises PM already proves: slots name version streams,
  generations accumulate, one atomic flip picks the live one, rollback
  restores, remove unlinks, and pruning stays separate and explicit.
- Two pins per adapter: the boundary version it implements, and the
  agent version it was verified against. A program built against a new
  boundary refuses a stale adapter by name.
- The contract itself is versioned: PM records which contract version
  each program and adapter implements and refuses disagreements.
* Name and location
- name: the pins are fields a declaration carries; the records and the
  flip already have owners, and no new names are needed beyond the
  registered ones
- code: =src/spec/= declares the pins, =src/store/= records the
  versions, =src/install/= flips and rolls back
- area and layer: =spec= (5), =store= (8), =install= (11); each piece
  sits in its area's existing direction
- may require: as each area already may
- may be required by: =entry=
* Public interface, in plain words
- install an adapter like any package; roll back like any generation; a
  boundary or contract mismatch is a refusal naming both sides'
  versions, before anything is replaced.
* What it must never do
- Never guess a version: disagreement is refused, not coerced.
- Never pin the contract to an adapter's worst version: rollback exists
  so a bad adapter is replaced, not tolerated.
* Tests
- =tests/spec/=, =tests/store/=, =tests/install/=; one fixture: install
  a newer boundary, see the stale adapter refused by name, roll back.
* Docs it updates
- =plan/OPEN-DECISIONS.org= (the entry closes); the register.
* Depends on new components
- none required; it uses PM's generation machinery as it exists.
* Build order
- After =hermes-integration= names the second adapter.

#+TITLE: AI-sight files — PM state an agent reads directly
#+AUTHOR: Shape
# One job: a small set of stable, machine-readable files describing PM
# state, so an agent reads instead of asking. Status: planned only;
# nothing here is built. Source:
# =../../pm-integration/ai-sight-files.org=; the home is the owner's
# open question.

* Purpose
- Reading state from files beats parsing narration: stable, cheap, and
  it needs no heartbeat. The set: installed packages with versions, the
  current generation per profile, the last build and bake results, and
  where the event feed lives.
* Name and location
- name: one name per file, registered in step 3
- code: written by the area that owns the state, at the moment it
  changes (final home is the owner's open question)
- area and layer: each file sits with its state; =entry= reads it
- may require: nothing above its own area
- may be required by: =entry=, senders, the kit entry
* Public interface, in plain words
- one file per state; read one key and get the current truth; written
  atomically with the change, never on a timer.
* What it must never do
- Never poll or heartbeat: written when the state changes, only then.
- Never a second truth: the state's owner writes it, not a copy job.
* Tests
- one test per file: after the change the file says so; before, it
  says not.
* Docs it updates
- the register; the file list becomes part of the kit entry.
* Depends on new components
- none: it precedes its consumers.
* Build order
- Early among group (b): senders, the kit entry and =install-then-bake=
  read it.

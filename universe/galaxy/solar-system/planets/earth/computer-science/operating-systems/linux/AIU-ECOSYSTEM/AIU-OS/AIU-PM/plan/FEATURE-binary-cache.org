#+TITLE: FEATURE binary-cache — build once, reuse by content hash
#+AUTHOR: Shape

Design only. No code lands with this file.

* Goal
Build an identical tree once and reuse the result by its content hash. This
extends the planned content-addressed overlay: the overlay stores artifacts
by hash, and this cache is the reader that skips a build when the hash is
already there. A cache is never a source of truth — verify re-hashes before
trusting it.

* Command shape and operands
No new verb. The cache is a store the existing build path consults. =verify=
already re-checks a pin; it must also re-hash a cached artifact before
trusting it, and drop it (narrated) when the hash disagrees.
Reads: the source tree it is about to build, that tree's content hash, and
the cache directory.
Writes: the cache entry for a freshly built artifact.

* Area
=store/content-address.rkt= — hash a tree, store and fetch artifacts by hash,
and reclaim the cache by pure reachability.
=build/build-cache.rkt= — the reuse decision: hash the tree, look it up, skip
the executor on a hit, run it on a miss. build sits above store, so it may
require it; the store never reaches up.

* Refusals
- verify refuses a cached artifact whose re-hash does not match, naming the
  artifact and both hashes, and drops it from the cache.
- A cache hit whose stored hash cannot be read is a miss, not a failure.
- A build is never skipped when its hash could not be computed.

* Narration
- STEP "hash" naming the algorithm and the digest.
- DECIDE "reuse" or "rebuild" on a hit or miss, naming the cache entry.
- SKIP the executor on a hit, naming the entry reused.
- WARN when an entry is dropped for a hash mismatch.

* JSON output keys (fixed order)
No new command, so no new envelope. The apply and build documents gain, in
fixed order after the existing keys: =cached= (boolean), =hash=, =cache-entry=.

* Open questions
- Hash algorithm: one tree hash over path, mode and content, or per-file
  digests combined? The combined form is one value to compare but harder to
  debug.
- Does a dev-mode checkout ever consult the cache, or is it always a rebuild?

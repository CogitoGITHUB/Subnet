#+TITLE: Rule 09 — Language split
# One job: the hard rule and what it demands in this program
# Status: current; the rule text is the owner's and changes only with the owner.

* The rule
# the owner's words, repeated unchanged. Do not soften or reinterpret them here.
  Language split. Racket wherever it makes sense, especially the config and meaning side: what
  exists, where it sits, what it shows, keymaps, commands, rules, semantic models. Rust where
  speed in use needs it, especially the UI and everything on the hot path: input, drawing,
  layout, terminal handling, parsing. The plan must name the exact seam: where Rust is needed
  for speed in use, where Racket stays, and how Racket joins a baked binary that loads nothing
  at startup; test first whether the Racket minimal build on this phone can support that. Nu
  for scripts, JSON for data, Television as the picker. Pure logic, effects only at the edges,
  small testable modules, paren-check after every Racket edit, compiled output stays in-tree.

* What it demands here
# how this rule bites in this program. No examples; the plan carries the detail.
  Rust owns the hot parse path; Racket owns meaning, the element names and the semantic model.

* What breaks it
# the failure this rule exists to prevent.
  Speed work written in the description layer, or meaning written on the hot path.

* Where it is proven
# the checklist item that shows this rule holds; named 2026-10-16.
  checklist/tier-1 items 01 and 18

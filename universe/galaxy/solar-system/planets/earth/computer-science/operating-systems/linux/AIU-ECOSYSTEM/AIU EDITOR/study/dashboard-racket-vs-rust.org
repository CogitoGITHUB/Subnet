#+TITLE: Dashboard: Racket vs Rust
# One job: what becomes Racket config and what stays in Rust for the dashboard
# Status: filled 2026-10-16 from Cyberdeck-Emacs, read-only; not yet reviewed.

* What becomes Racket config
# the dashboard parts that are description and meaning: what exists, what it shows, keymaps, commands, rules.
  - The desk's contents: which sections exist, their titles, their order (the
    order file as data), and which pieces are structural (banner, footer).
  - Widget declarations: name, how many items it shows, and what it shows —
    the meaning of each section, not its drawing.
  - The bar's layout: which segments sit on which row and side, and the
    fallback bar's contents.
  - Refresh policy as declared rules: what refresh follows which event, the
    throttle windows, the cache lifetimes.
  - Startup policy: show the desk only when no file was requested; which
    sources may run at open (the bounded-agenda rule).
  - Aesthetics: banner words, footer lines, and the mono emphasis rules.
  - Validation and scaffold rules: one file per widget, orphan checks, order
    audits.

* What stays in Rust
# the parts on the hot path: input, drawing, layout.
  - Drawing the desk: composing the panel, laying out the banner box for the
    width, rendering items, truncation and path shortening.
  - Drawing the bar: composing segment strings into two minibuffer rows,
    truncation, repainting on update.
  - The refresh engine: timers, event subscriptions (save, resize, state
    change), throttle counters, in-place section rewrites.
  - Fast value production for segments: position, buffer name, branch, store
    state, clock values, plus the format templates from config.
  - Data gathering from engine-owned stores (the new program's own recent
    lists, projects, agenda), replacing what the old config read from editor
    libraries.

* The exact seam
# where the two meet, named precisely; this is the seam rule 09 demands.
  - The seam is a rendered panel description: Racket declares sections,
    segments, order, limits and policy; Rust asks for the declarations and
    draws.
  - Concretely: Rust owns (row, side, segment) lookup, value production and
    the drawing; it never hardcodes a section name, an order, or a throttle.
  - Racket never draws: it cannot compute a width, compose a line, or own a
    timer; it only says what exists and what it shows.
  - Same split as the keyboard: the baked binary carries the declarations;
    work mode rebuilds them from source and never touches the draw path.

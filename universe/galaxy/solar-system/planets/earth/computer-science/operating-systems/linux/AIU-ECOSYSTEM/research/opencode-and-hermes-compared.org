* What it is
# the project, its language, its health, and who maintains it.
  Both are MIT-licensed, terminal-first agent CLIs, extremely active (last
  pushes 2026-10-16) and large: OpenCode in TypeScript (214k stars,
  coding-agent focus), Hermes Agent in Python (254k stars, long-running
  personal-agent focus). Both speak MCP, both run a tool loop with subagent
  delegation, both ship install scripts and package managers.

* What transfers
# one line per mechanism worth borrowing, each with the reason it fits a program here.
  - One agent-neutral boundary: the shared shape (tools + loop + subagents)
    means a single internal contract with pinned adapters can front both.
    The adapters stay thin.
  - Take each one's distinguishing seam: approval rules and a headless
    loopback server from OpenCode; skills/memory/backend abstraction and
    Termux packaging from Hermes.
  - Both keep instructions in files (AGENTS.md rules; context files) — the
    cross-agent convention we already rely on.
  - Keep the difference visible: OpenCode is a coding session on a repo;
    Hermes is a persistent personal agent. One surface, two modes, not a
    feature union.

* What to avoid
# one line per mechanism we deliberately do not take, with the reason. No code.
  - Running both as first-class from day one: one adapter pinned, the second
    validated behind the same contract, else the boundary doubles.
  - Any consolidation by feature union: the overlap is the loop; the value is
    in the distinct edges.

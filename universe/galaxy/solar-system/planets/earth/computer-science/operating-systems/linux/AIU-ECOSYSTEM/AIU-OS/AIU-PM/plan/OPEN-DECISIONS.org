* The blocked and parked work

** E-16b pm fetch -- BLOCKED
- *Purpose:* fetch and pin every declared package into the vault,
  without building, skipping ones already present, reporting
  new / already present / failed per package.
- *State:* the command is implemented and every single-add path is
  green. What fails is the SEQUENCE.
- *Root cause:* 3 or more sequential =vault-add= calls inside one
  shared test-runner process freeze with zero CPU and no live child
  processes (frozen 162s after the ff-b refmap). Six fresh adds
  standalone pass; one broken URL alone passes. All 155 children had
  already exited, so this is a pure-Racket block, not a slow git.
  The suspects are =child.lock=/=flock= plus a waiter-miss family in
  the run.rkt / vault child management. Repro: the full
  =package-manager/src/store/update.rkt= suite.
- *Decision:* =(DEFAULT: isolate the wedge in =package-manager/src/git/vault-lock.rkt= and
  the run.rkt waiter, fix it, and keep E-16b BLOCKED until a 3-package
  fixture passes in one process.)=
  - (a) Hunt the wedge now and fix it. Recommended: E-16b/E-16c and
    the CLI fetch all wait on it, and it is the only thing between pm
    and a working =fetch=.
  - (b) Park it and ship single-add. Rejected: =pm fetch= on a real
    declaration with 2+ packages would still hang, which is the actual
    user path.
  - (c) Give each add its own process. Rejected as a workaround: it
    hides the bug and multiplies startup on a phone.

- *Blocked by:* E-16b. Parallel cannot go green while sequential

* BLOCKED, platform: the parent cannot hold a fifo writer open
:PROPERTIES:
:END:

The =run-command= fifo strand is FIXED at its cause: =#:cwd= is now
validated in =spawn-prelude= before anything is created or spawned, so a
nonexistent directory raises a named =exn:fail:pm= instead of letting the
child die in =chdir= before the wrapper's first act. That was the whole
of the measured hang (package-manager/src/git/git-repo.rkt, 7+ minutes on a =git-has-commit?=
against a =demo.git= that was never created).

What is NOT done is the belt-and-braces part: having the PARENT hold a
fifo write end so the reader can never lack a writer. Racket 9.3 cannot
express it. Probed in a scratch file, all three file-open functions:

| call | result on an existing fifo |
|------+-----------------------------|
| =open-output-file= (=#:exists 'error=) | raises "file exists" |
| =open-output-file= (truncate/replace, update, append) | RETURNS AT ONCE, never blocks |
| =open-input-output-file= | raises "file exists" |

=open-file-output= does not exist in this Racket. So there is no call
that BLOCKS on a fifo write end, which is precisely what a holder needs.
The holder was written, measured not to work, and removed rather than
shipped with a comment claiming a guarantee the code did not provide.

Consequence, stated plainly: if a child dies before the wrapper's first
act for some reason other than a bad =#:cwd=, the reader still parks in
=open()= on the fifo read end with nothing to wake it. The wait on the
child now goes through the wait door (=wait-for=), so such a block is
narrated rather than silent, and the cwd guard removes the one path
observed in practice.

- *Recorded as ACCEPTED-MITIGATED* at the run.rkt split (MOVE-ORDER step
  4). The cause is fixed and measured; the belt-and-braces holder is
  impossible in Racket 9.3 and was removed rather than shipped
  pretending. It is not a live bug and it is not silently dropped.

* The mirror's two open questions, decided

** Where the mirror repo lives
- *Question:* a new XDG config root, or a sibling of the vault?
- *Options:* (a) new XDG root, =<state>/mirror-repo=; (b) sibling of
  the vault, so it sits next to the thing it backs up; (c) inside the
  vault, as a subdirectory.
- *Recommendation:* (b). The vault is the one location that is already
  git-owned, already a sibling of the store, and already on the same
  volume as the state it backs up. A second XDG root adds a place to
  configure for no gain.
- *(DEFAULT: (b), the mirror repo is a sibling of the vault under the
  state root, overridable by =PM_MIRROR_PATH= exactly as the vault is
  overridable by =PM_VAULT=. Not configurable means SKIP, never error.)*
- *Rejected:* (c). Putting a git repo inside another git repo is how
  you get a backup that silently never gets pushed, because the outer
  repo treats it as an ordinary directory.

** Does a push retry block the caller
- *Question:* block in the wait door, or run detached and record the
  result?
- *Options:* (a) block, narrated; (b) detached, with a result record;
  (c) neither, fail the fetch.
- *Recommendation:* (a). D-015 forbids timers, and a detached push needs
  somewhere to record its result and something to wake it; that is a
  second queue, and =P-03= already showed that a queue is a second way
  to be stuck.
- *(DEFAULT: (a), the push runs inside =wait-for= with a non-blank why,
  and a push failure warns and leaves the commit local for the next run
  to retry. A mirror failure NEVER fails the fetch that preceded it.)*
- *Rejected:* (b) and (c), for the reasons above and because (c)
  violates the mirror's first invariant.

* A fifth module in the plan split, and why
MOVE-ORDER step 3 named four new modules for =package-manager/src/spec/plan.rkt=. Reality
needs five. The twelve action structs plus =plan= and =package-plan=
must live somewhere that is NOT the facade, because the facade
re-provides them: a module that re-provides cannot also be required by
what it re-provides without a cycle, and Racket rejects cycles at
compile time rather than at run time. So the data model gets its own
=plan-actions.rkt= and the four job modules sit above it.
- *Decision:* =(DEFAULT: five modules. A module with no code of its own is
  not a violation of one-file-one-job; a module with two is.)= The
  amendment is recorded in =plan/MOVE-ORDER.org= in the same commit that
  makes it true.

* D-027 reversed: compiled output leaves the tree
- *What D-027 said:* do NOT set =PLTCOMPILEDROOTS=. Measured on this
  phone, ="<cache>:same"= -- two roots, the second the literal value
  ="same"= -- made =raco make= 401s and =raco test= 216s on a 2-module
  project against 18s unset. The stated cause was that the first root is
  the write root and Racket re-emits its own stock libraries into it, so
  the cache grows without bound. =compiled/= stayed in-tree and
  gitignored.
- *What was measured instead:* ONE root, no =":same"=. Loading
  =racket/list= and =racket/string= with the root set left the root at
  its previous file count and mirrored no =collects/= or =pkgs/= path
  into it. The stock-library re-emission does not happen in this
  configuration, so the 401s does not follow from it. Mechanism tested
  before any config was written; see commit f792eca.
- *Decision:* =(DEFAULT: keep the single root. A cold root costs one
  rebuild, which is what a fresh checkout costs anyway. If a stock-library
  tree ever appears under the root, D-027 was right after all and this
  gets reverted with that directory as the evidence.)=
- *Not silently dropped:* the old note stays in =gate/env.nu=, because
  a reader who remembers D-027 needs to find out it was reversed and why.

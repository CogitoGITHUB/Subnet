#+TITLE: Install then bake
# One job: how PM's install feeds a program's dev-mode bake
# Status: filled 2026-10-16; planned only, PM itself is not touched here.

* What PM must gain
# the capability in words; the exact PM files are named only after PM is read, until then say where to look later.
  - A defined finish line for install: record the installed generation in
    the sight files, so the program's dev-mode loop can see exactly what
    changed.
  - The bake itself stays the program's own loop (live from source, bake,
    keep last good, manual rebuild, measured start); PM asks for it
    explicitly — bake is a named action (mcp-surface.org), never a silent
    side effect of install.
  - No timers anywhere in the chain: the bake starts on the completion
    event, never on a watch loop.

* Shape
# how the entry, surface or file looks from the outside. No code.
  - Order: install places a generation and flips the link; the sight file
    names version and path; the bake reads the source and the installed
    pieces and produces its artifact; a re-bake with unchanged inputs
    SKIPs by content hash.
  - Fail closed: a failed bake keeps the last good artifact; a cancelled
    install leaves the old current untouched.

* Proof that it works
# the one check that shows this is done when the PM prompt runs.
  - Install a changed version, bake: the artifact rebuilds and its start
    is measured; run bake again unchanged: every step SKIPs naming the
    matched hash; break the bake: the last good artifact still runs.

* Owed to the PM checklist
# one line per PM change, added to pm-change-checklist.org.
  - Define the install-completion record the bake reads; prove the
    unchanged-bake SKIP and the keep-last-good path.

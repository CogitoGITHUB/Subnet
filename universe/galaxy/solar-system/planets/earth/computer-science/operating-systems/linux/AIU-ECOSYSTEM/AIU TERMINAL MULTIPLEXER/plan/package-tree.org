# One job: the package directory, the area law, and every planned directory and file with its single job
# Status: planned 2026-10-17; this file is the register for the package — a name that is not here does not exist yet.

* The package directory
# one subdir holds the whole package; nothing is scattered.
  - The package is =multiplexer/=, directly under this project
    directory. The project root keeps context and docs (plan/, rules/,
    ui/, ai/, dev-mode/, research/) plus gate/, tools/ and agent/ —
    the same split as PM's =AIU-PM/package-manager/=.
  - =multiplexer/INDEX.org= is created with the directory, one job per
    line; every subdirectory carries its own INDEX.org.
  - Nothing of the package lives outside =multiplexer/=.

* The law
# areas lowest first; dependencies point one way; the language seam is named.
  - Areas, lowest first; a require may point downward only. The
    one-way lint transcribes this table as its source:
    errors, narration, machine, security, join, devloop, tty, holder,
    panes, routing, layouts, records, client, agents, control, entry.
  - errors is the floor; entry is the ceiling.
  - Rule 09, named exactly: Rust owns terminal handling, input,
    drawing and layout — =tty/=, =holder/=, =routing/= and the
    client's drawing; what exists and how it shows is Racket config —
    layouts, records, settings, keymaps. The seam is =join/=: the only
    place the two languages meet, and how the meaning side loads in
    the baked binary that loads nothing at startup.
    =gate/language-split-lint.nu= keeps every other area clean.
  - One file, one job; the reader test on every name; banned words as
    in the ecosystem law.
  - The table is the plan; the first lint run lists any crossing it
    inherits, and each one gets a recorded decision, never silence.

* What starts first
# the first files, tied to the build order.
  - Lands first, with the light gate: errors, narration, machine and
    the =multiplexer/= INDEX.org — the floor every later file stands on.
  - The first slice (checklist/tier-1 items 02–04): the tiny-binary
    probe on this phone (it decides the route, D-002), then tty/ and
    holder/ (a shell in a terminal that survives detach), then panes/
    and layouts/ — panes working, blocked or idle, truthfully.
  - While ours is built, herdr runs the daily panes if the probe
    passes (D-003); the contract stays the same either way.

* Absent on purpose
# what similar programs carry and this one will not.
  - No plugin runtime; no config and no timers in the holder; no
    process survival promises; no desktop or web clients; no editing
    features; no agent logic (the adapters' job).
  - No core/, utils/ or description-name directories, ever.

#+TITLE: Event log format
# One job: the one event record every program writes: who, why, UTC, duration, structured fields
# Status: filled 2026-10-16; working draft until a program and an adapter both depend on it.

* What this freezes
# the exact thing every program and adapter must obey; if it is not frozen here, authors guess.
  The one event record every program writes, so feeds from different
  tools stay mutually readable. Lifted verbatim from the package manager
  where it already runs; restated here as the contract.

* Shape
# names and meanings only: the fields and what they promise. No code, no examples.
  - run-id, seq, parent-id, kind, depth — identity and nesting; seq is
    one counter per run shared by nested operations, never restarted per
    level; parent-id points at the enclosing start event.
  - who, what, why, how — the story; why is mandatory for step, decide,
    skip and failure — a skip without a reason is a bug in the caller.
  - inputs, outputs, result — operands and outcome.
  - utc, mono-ms, duration-ms — utc is wall time for humans; duration
    and mono come from the monotonic clock, never wall time.
  - kind is a closed set: start, step, info, decide, skip, progress, end,
    fail, warn.
  - Flushed per record: a killed process leaves a readable prefix, never
    a torn record.
  - The three destinations are the same record: the screen line, the
    JSON Lines log and the AI feed file.

* Who obeys it
# every program and adapter this applies to, named.
  Every program — editor, notation, multiplexer, PM — and every adapter.
  The kit's plugin reads the feed; the sight files carry the summary
  beside it.

* How it changes
# how this can change without breaking a running client; point at a D-number once one exists.
  Additive fields only keep readers working; readers ignore what they do
  not know. The kind set is closed and changes only with a contract
  version bump. Freeze condition: when a program and an adapter both
  depend on it; the D-number lands in the program that freezes it (none
  yet).

* Open decisions
# options with a recommendation, or none yet.
  - Where each program's feed file lives — recommendation: beside its
    sight files, from the one scope seam.
  - The holder's own log: recommendation — the same field shape, written
    with no config and no timers; confirmed in the multiplexer's plan.

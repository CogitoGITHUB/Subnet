#+TITLE: Keyboard mechanisms
# One job: every mechanism the keyboard layer combines, one line each
# Status: filled 2026-10-16 from Cyberdeck-Emacs, read-only; not yet reviewed.

* The mechanisms
# every mechanism the keyboard layer combines, one line each, described plainly.
  - Modal state machine — one buffer-local state per buffer; the set-state
    function is the only assignment point; 12 states, each a self-registering
    minor mode.
  - State registration — a state file defines its mode and keymap and registers
    itself; deleting the file unregisters the state on the next boot.
  - Key binder — one form binds state, substate, keymap, global and inherited
    keys; all keys go through the modern keymap API.
  - State registry — a state-to-init-fn alist, newest first; precedence is
    explicit, never positional.
  - Init predicates — a state activates automatically when its predicate says
    so (org buffer, read-only buffer, dired, ibuffer).
  - Precedence order — an explicit list ("org" "dired" "ibuffer" "motion") is
    consulted before the rest, so colliding predicates resolve the same way.
  - Shared bindings — one file merges keys into several states at once; it
    loads late because it references the other states' keymaps.
  - Leader hub — SPC opens the root menu; each leader file owns one submenu;
    the hub links submenus by symbol at runtime.
  - Menus — state menus walk the live keymaps, leader menus come from their
    declarations, and one small table maps SPC sub-keys to menus; no
    hand-listed key summaries.
  - Sticky keys — a binding marked sticky keeps its menu open for repeats.
  - Chord engine — two plain keys pressed together or double-tapped dispatch
    as one event; defined globally or locally; carried by the input method.
  - ESC/Meta disambiguation — terminal-only: an input filter waits a short
    delay to tell a standalone ESC from a Meta prefix; both work; off by
    default.
  - Smart escape — ESC returns to the state the buffer calls for (org, else
    normal).
  - Key selection — vendored jump engine under a local prefix: tree-style
    jumps, selections, and actions (copy, kill, move, zap; windows included).
  - Region algebra — Boon-extracted helpers that treat mark, point and cursor
    as one value, used by several commands.
  - Highlight engine — Boon-extracted: highlight a pattern; jump forward and
    backward over its occurrences.
  - Smarter motion — forward, backward, up and down move over whole syntactic
    units and indentation levels, not characters.
  - Act family — Embark-extracted: act on the thing at point by type (region,
    file, URL, buffer, symbol); cycle candidates, highlight, batch all.
  - Repeat-last — remembers the last command run from a state keymap, with its
    prefix argument.
  - Count and execute — read a count, then one key, run that command with the
    count.
  - Quoting — run the key's command with the modal layer bypassed for one key.
  - Undo collapse — a Meow-extracted macro groups several edits into one undo
    step; the atomic zap uses it.
  - Line and mark commands — line beginning/end cycling, line-content yank,
    spacing fix, reindent chain, mark pop and unpop.
  - Modeline link — every state change is announced so the bar can show the
    state name; relative line numbers follow suit.
  - Creators — small commands write new state or leader skeletons; the module
    directory is derived from the file's own location.
  - Validator — checks tags, duplicate keys, unbound commands, dead states,
    docstrings and evaluation order; writes one validation buffer.
  - Package keymaps — treemacs, vundo and git-timemachine get direct keymap
    edits; two of them clear the state while active.

* How they combine
# the order input passes through them.
  - At load the declarations carry their own order: engine (macros and the
    state machine) first, then the extracted cores, then menus and scaffolding,
    then leaders and states, then the shared bindings file, then setup for
    hooks and activation.
  - At runtime a key hits the input filters first (chord timing, ESC/Meta
    disambiguation), then the active state's keymap, which already contains
    the shared bindings; ordinary minor modes and the global map sit below.
  - State selection is separate from key resolution: buffer init, mode hooks,
    smart escape and explicit switches change the state; the state picks the
    keymap.
  - Menus are reached from keys and re-derive from the same keymaps, so a
    binding and its menu entry cannot drift apart.
  - Quoting is the one deliberate bypass: it resolves the key against every
    map except the state keymaps.

* What is portable
# which mechanisms are not specific to the old config and can travel.
  - The state registry with predicates and an explicit precedence order.
  - Keys as data: state-to-key-to-command tables, shared sets, menus declared
    once.
  - Leader tree with runtime links, sticky keys, count-then-key, repeat-last.
  - Act-on-thing, candidate cycling, batch actions.
  - The timing ideas: chord delay and ESC/Meta disambiguation need only a
    tunable timer at the input layer.
  - Jump/selection engine logic and region algebra semantics.
  - The discipline around it: creators, validator, registration by dropping a
    tagged file.

* Specific to the old config
# which dashboard mechanisms only make sense inside it, one line each with why.
  - The desk renders into a read-only editor buffer using text properties and
    buffer-local state; there is no separate drawing surface.
  - The bar renders through mode-line constructs shown in the minibuffer by
    mini-modeline; the real mode line is a per-window object of the editor.
  - Refresh hooks are editor hooks (after-save, window-size-change,
    after-init, find-file) and the timers are editor timers.
  - Data sources are editor libraries: recent files, bookmarks, projects,
    registers, agenda, version control — each with its own quirks (the agenda
    walk, the per-save recentf cost).
  - The widget DSL is an editor macro expanding into generator functions and
    an item alist; registration is an alist push.
  - Faces, olivetti, page-break-lines and the fuzzy clock are package-shaped
    layers of the old editor.
  - The vendored upstream code is an editor package kept whole and diffed
    against upstream; that maintenance shape only exists here.

* Portable
# which mechanisms survive a move to a fresh program.
  - The desk model: sections as name, length and render declarations; order
    as a data file; registration by file drop.
  - Composition rules: banner structural, items data-ordered, footer last;
    stock sections and local widgets distinguished and pruned differently.
  - The bar model: segments as pure single-line functions; rows and sides as
    data; the two-line pairing invariant; a sick segment shows "?".
  - Refresh discipline: cached slow values, event pushes, in-place partial
    rewrites, throttled full redraws, debounced resize.
  - Startup policy: show the desk only when there is nothing else to show;
    bound any source that would walk the whole store; degrade to a plain bar
    on failure.
  - Validation discipline: registry against reality, orphan checks, order
    audits.
  - The mono, letter-first bar intent: emphasis by weight and position.

* The cut line
# where the split is drawn, in one or two lines.
  - Editor-specific is the surface — buffer text properties, mode-line
    constructs, minibuffer display, hooks, library data sources; portable is
    the model — sections, order, registry, segments, rows, refresh policy.
  - Anything named after an editor object (mode-line construct, buffer-local
    variable, hook) must be re-expressed; the declarations and invariants
    cross over.

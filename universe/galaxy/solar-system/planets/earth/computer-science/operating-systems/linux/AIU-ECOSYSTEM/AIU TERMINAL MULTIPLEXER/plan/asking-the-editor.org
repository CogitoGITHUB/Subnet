#+TITLE: Asking the editor — the multiplexer asks the editor's own server
# One job: how the multiplexer asks the editor for what the editor owns, and
# what the answer is when it comes back
# Status: written 2026-10-22 from TODO item 16; the code lands with the item.

* What the item asks
# the one sentence the item owes, in the item's own words.
  - "The multiplexer asks the editor for what the editor owns." The editor
    owns its buffers and their text, its tab order and its active tab, its
    window layout, its point and its selection. The multiplexer owns its
    tabs, its panes and its focus. Neither may answer for the other.

* What the seam is
# the smallest true statement: the editor's own surface, over its own wire.
  - The editor already ships a surface an agent can read: its MCP server
    (AIU EDITOR/editor/src/entry/mcp.rkt), one JSON-RPC object per line, one
    answer per line, with the capabilities declared as data. The
    multiplexer asks THAT server, over that wire, for a read-only
    capability: the dashboard, which is the editor's own state as the editor
    draws it.
  - The ask is the editor's own words. The multiplexer does not translate
    them, does not summarize them and does not explain them: the panel shows
    what the editor said, and a refusal is shown as a refusal with the
    reason the editor gave.
  - The read is free and the editor's own engine re-checks it: the
    capability is declared read-only in the editor's own table, and the
    server refuses a tool that is not declared. The multiplexer never asks
    for anything that changes the tree.

* Who holds the child
# the rule that decides where the ask runs.
  - The HOLDER asks, not the client. The client holds nothing: it holds no
    shell, no log and no child process, so a client that ends takes nothing
    with it (rule 01). The holder is where the session's processes live.
  - The holder spawns the editor's server, speaks the editor's wire to it,
    and answers the client with the editor's words. The screen asks the
    holder for the ask, exactly as it asks the holder for the Git state and
    the workspace.

* The command is given, never written
# the language rule, and what it means for this file.
  - The command that starts the editor's server is given at run time: the
    program and what it runs, one word at a time, so a path with a space in
    it is still one path. No file of the multiplexer names a program of the
    editor, and no file of the editor names a program of the multiplexer:
    the two languages meet only in the join area (D-028).
  - Without that command there is nothing to ask, and the ask is refused BY
    NAME: "there is no command for the editor's server". The multiplexer
    never guesses a program and never searches a filesystem for one.

* What the owner is told while it waits
# the rule about blocking, and the shape of the answer.
  - The editor's server takes a while to start on this phone: about ten
    seconds, measured. The mode line says so BEFORE the wait, and the
    answer says how long it took, so a wait is never a silence.
  - The answer carries the editor's text, the capability that was asked
    for, and the time it took. An answer with no words is said to be empty:
    an empty panel is not an answer, and the owner must not read one as
    one.

* The proof
# what must hold before this is called done, in the order it is seen.
  1. The owner presses =w e= (the workspace group, "ask the editor").
  2. The mode line says the editor is being asked, and that its own server
     starts first.
  3. The editor's server is asked, over the editor's own wire, for a
     read-only capability.
  4. The panel shows the editor's own words, and the answer names how long
     the ask took.
  5. Nothing in the editor's tree changed: the ask was a read, and the
     editor's own engine checked that.

* What it does not do
# the refusals, each with the rule it refuses by.
  - It does not ask for a change: only a read-only capability is asked for,
    and the editor's own declaration is the gate (rule 07).
  - It does not scrape the editor's screen and does not copy its text by
    hand: the words travel over the editor's own wire.
  - It does not start a second editor: the editor that answers is the
    editor's own server, asked once, and the child ends with the answer.
  - It does not use a timer: the wait ends on the answer the child sends.

* What landed
# the shape that is in the code now, and where the proof is.
  - The holder's seam is =src/holder/editor.rs=: it starts the editor's
    server, sends the handshake and the read, reads the two answers, and
    answers with the editor's own words and the time it took.
  - The holder's op is ="editor"=, and it is a record like every other: the
    session's log says what was asked, of what, and how long it took.
  - The screen's key is =w e= in the workspace group, and the panel is
    drawn by =src/client/editor.rs=: the editor's own words, one line per
    row of them.
  - The proof is =tools/editor-probe/probe.nu=: the ask goes to the real
    editor's server, and the answer is the editor's own dashboard.

#+TITLE: Architecture in the plan — AIU NOTATION
# One job: the named pieces, how they fit, the seams, and what is deliberately absent
# Status: filled 2026-10-16; plans stay general, not yet reviewed.

* The pieces
# the named parts, one line each: what it is and its one job.
  - syntax — the element language at concept level: literal names, one
    tiny consistent mark, paragraph as the default (rule 12).
  - parser — the context-free core: incremental reparse and error
    recovery on partial text (hot path; language-split rule).
  - nodes and addressing — what a node is and how a send names it
    (contract step 9: node addressing and comments).
  - literate chunks — named chunks, targets and dependency scanning;
    load in place or send into other files; content-addressed reuse.
  - comments — first-class in the text; rendering strips them.
  - rendering — plain, rich unicode, and the optional graphics tier
    planned only.
  - engine surface — the notation side of the boundary the editor and
    the multiplexer call (the LSP-like seam; contract step 9).
  - semantic models — what exists, where it sits, what it shows; the
    meaning side, in Racket per the language split.
  - tiers — the everyday tier now; math, graphs and the advanced syntax
    are tier 3, plan only (checklist/tier-3/).

* How they fit
# the direction of dependency between the pieces, one line per arrow.
  - syntax → parser → nodes; rendering reads nodes; nothing renders what
    the parser did not produce.
  - comments ride in the text; rendering strips them; nothing else strips
    anything.
  - literate chunks sit on nodes and targets; dependency scanning reads
    them; a changed chunk rebuilds and an unchanged one SKIPs by hash.
  - while editing, the session owns truth and the file is storage; on
    save the text wins.
  - the engine surface is called by the editor and the multiplexer; it
    calls nothing back into them.

* The seams
# where another program plugs in, and through which boundary.
  - The editor — through the notation-engine boundary (contract step 9);
    the editor triggers the engine build and enters dev mode after it
    (rule 14).
  - Agents — a send carries the notation address inside the context
    bundle (contract step 9).
  - PM — install, then bake in (rule 02); the notation is a package with
    its own kit like every program.
  - The kit — its own JSON surface, MCP server, skill and read-only
    plugin (ecosystem rule 2).

* Absent on purpose
# parts similar programs carry that this one will not, with the reason.
  Math and graphs engines now (tier 3); a general-purpose engine beyond
  the language's need; editor features (the editor's job); silent
  formatting opinions — rendering shows, the text rules.

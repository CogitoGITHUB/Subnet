#+TITLE: Keyboard: specific vs portable
# One job: which keyboard mechanisms are specific to the old config and which travel
# Status: filled 2026-10-16 from Cyberdeck-Emacs, read-only; not yet reviewed.

* Specific to the old config
# which keyboard layer mechanisms only make sense inside it, one line each with why.
  - State keymaps ride the emulation keymap level — a precedence mechanism of
    the old editor's keymap machinery.
  - Chords install as an input method and read the second key with timers —
    both hooks are the old editor's event loop.
  - ESC/Meta disambiguation rewrites the terminal's decode map — a shape only
    a terminal-facing editor has.
  - Menus are Transient declarations; the declaration shape outlived the Hydra
    engine, but the engine itself is a package of the old editor.
  - Package keymaps (treemacs, vundo, git-timemachine) are third-party keymaps
    of the old editor.
  - which-key discovery, the modeline announcement, buffer-local state
    variables and major-mode hooks.
  - Commands act on old-editor notions: kill ring, registers, mark ring,
    thing-at-point, derived major mode.
  - Region algebra helpers are markers; the highlight engine uses overlays and
    font-lock.
  - The validator inspects keymaps and the command index of the old editor.

* Portable
# which mechanisms survive a move to a fresh program.
  - The state registry: states, activation predicates, explicit precedence —
    data plus small pure functions.
  - Keys as data: per-state tables, shared sets, menus declared once.
  - The leader tree with runtime links and sticky entries.
  - Count-then-key, repeat-last, one-key bypass (quoting).
  - Act-on-thing, candidate cycling, batch over all occurrences.
  - Chord timing and ESC/Meta disambiguation as input-layer concepts with a
    tunable delay.
  - Jump/selection: candidate collection, per-char selection, actions.
  - Region algebra and smarter-motion semantics (whole units, indentation
    levels).
  - The discipline: creators write skeletons; validation checks duplicates,
    unbound commands, dead states and evaluation order; registration is
    dropping a tagged file.

* The cut line
# where the split is drawn, in one or two lines.
  - The split is dispatch against meaning: key-event decode, timing, keymap
    precedence and redraw are the program's engine; state tables, predicates,
    menus and command wiring are description that crosses over in shape.
  - Anything named after an old-editor object (keymap levels, overlays,
    markers, hooks) must be re-expressed in the new program's own objects.

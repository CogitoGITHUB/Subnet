#+TITLE: Phone-first tests — AIU EDITOR
# One job: what must be proven on the phone first, what waits for the laptop, and how each is proven
# Status: filled 2026-10-16; plans stay general, not yet reviewed.

* Proven on the phone first
# one line per thing that must work on the phone before anything is built on it.
  - The minimal Racket build inside a baked binary.
  - Plain-text editing with keys, including the selection and send keys
    on the phone keyboard.
  - Journal and replay after a forced kill.
  - File-change events (inotify) reaching the editor under proot, with no
    polling.
  - What survives an Android background kill, recorded honestly.
  - The baked binary's measured start.
  - The dashboard's baseline drawing on the phone's terminal.

* Waiting for the laptop
# what the phone cannot prove; every line here is also appended to WHEN-ON-LAPTOP.org.
  - Long rebuilds when they exceed the phone budget — appended when
    measured.
  - Long test runs likewise.
  - The optional graphics tier for richer rendering — unproven on this
    terminal (already listed in WHEN-ON-LAPTOP.org).
  - Multi-hour uninterrupted work — the phone is a phone; planned
    around, not fought.

* How each is proven
# the single check for each phone-first item.
  - Racket join — the printed measured start of the baked binary on the
    phone.
  - Editing with keys — one real session on the phone keyboard, all the
    way through a send.
  - Journal and replay — kill the process mid-edit; replay; the buffer
    returns exactly.
  - Watch events — touch a watched file; the editor shows the change the
    moment it lands.
  - Kill survival — the observed facts are written next to the promise;
    the promise is never wider than the observation.
  - Measured start — the number the binary prints; information, not a
    gate.
  - Dashboard — it renders legibly on the phone's terminal.

#+TITLE: Dev-mode loop
# One job: the one dev-mode loop: live from source, bake, keep last good, manual rebuild, measured start
# Status: filled 2026-10-16; working draft until a program and an adapter both depend on it.

* What this freezes
# the exact thing every program and adapter must obey; if it is not frozen here, authors guess.
  The shared vocabulary and order of the dev-mode loop (rule 02): work
  mode loads config and plugins live from source; a manual rebuild bakes
  them into the binary as first-class defaults; the last good build is
  kept; the baked binary loads no config, opens instantly and prints its
  measured start. Install, then bake in.

* Shape
# names and meanings only: the fields and what they promise. No code, no examples.
  - States: work mode; bake; release.
  - A bake is manual, may run long, runs while work continues, and
    announces its completion as an event. No timers — a bake ends on an
    event.
  - Keep last good: a failed bake leaves the last good artifact running.
  - Measured times are information, not gates.
  - The PM chain: install places a generation and records it; the bake
    reads what changed (pm-integration/install-then-bake.org).
  - The mechanics stay each program's own; only the vocabulary, the
    order and these promises are shared.

* Who obeys it
# every program and adapter this applies to, named.
  Every program with config or plugins — the editor, the multiplexer, the
  notation. PM's own dev mode is the worked example
  (learned/versioning-and-rollback.org).

* How it changes
# how this can change without breaking a running client; point at a D-number once one exists.
  The shared words change only with a contract version bump; mechanics
  are per program. Freeze condition: a program and an adapter both
  depend on it; none yet.

* Open decisions
# options with a recommendation, or none yet.
  - Artifact location — recommendation: each program's state home, from
    the one scope seam.
  - Bake while a session is live — recommendation: it runs beside the
    work; completion is an event, never a wait.

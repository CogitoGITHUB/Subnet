#+TITLE: Adapter versioning and rollback
# One job: how PM versions and rolls back the agent adapters and the contract itself
# Status: filled 2026-10-16; planned only, PM itself is not touched here.

* What PM must gain
# the capability in words; the exact PM files are named only after PM is read, until then say where to look later.
  - The agent adapters (OpenCode, Hermes) installable as PM packages with
    exactly PM's proven promises: slots name version streams, generations
    accumulate, an atomic flip picks the live one, rollback restores,
    remove unlinks and pruning stays separate and explicit.
  - Each adapter declares two version pins: the boundary version it
    implements and the agent version it was verified against; a program
    built against a new boundary refuses a stale adapter by name.
  - The contract itself is versioned; PM records which contract version
    each program and adapter implements and refuses disagreements (the
    rebuilt-client case, contract step 9).

* Shape
# how the entry, surface or file looks from the outside. No code.
  - Adapter identity is content, not a label: name, slot, version plus an
    input hash; the flags that built it are recorded, so a profile cannot
    claim a build it did not make.
  - Fail closed on every failure path; the generation GC can refuse a
    held generation; dev mode stays the defined side channel.

* Proof that it works
# the one check that shows this is done when the PM prompt runs.
  - Install an adapter generation, roll back: the old boundary binding is
    live again and the program against it still starts; bump the boundary
    against an old adapter: the refusal names the adapter and both
    versions; a cancelled apply leaves current untouched.

* Owed to the PM checklist
# one line per PM change, added to pm-change-checklist.org.
  - Package the adapters with pins, flip and rollback; record contract
    versions with the same refusal discipline.

#+TITLE: The plain text slice — what was decided, and what it cost
# One job: the program-only choices of the first slice that edits text, and
# the reason for each. Registered in plan/package-tree.org; lands with TODO
# item 3.

* The decision
The first slice reads the typed lines on the RACKET side (entry/dispatch.rkt
reads them from the standard input) and calls the RUST hot path once per
command. The buffer and the journal stay Rust's (rule 09, D-007).

* Why
A pipe cannot carry the keys to a child in this Racket build: racket/system
hands a child /dev/null for every stream that is not a file stream, and the
copying threads die silently (the proof is in research/join-on-the-phone.org
and in the source of racket/system.rkt). The keys therefore arrive on the
Racket side, which is the only side that can read them here.

* What it costs
The hot path is spawned once per command, and the state between commands is
the file plus the journal: the saved text lives in the file and the unsaved
text lives in the journal, so nothing is lost when a process ends.

* What it takes to undo
The input/ area (read.rs) lands with the Rust session, when a stream can
carry the keys. Then the loop in dispatch.rkt moves into Rust, the Racket
side is asked for the meaning of a key rather than for a whole command, and
the answer comes back over the same file wire.

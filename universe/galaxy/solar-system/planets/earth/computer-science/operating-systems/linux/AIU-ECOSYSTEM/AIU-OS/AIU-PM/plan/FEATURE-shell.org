#+TITLE: FEATURE shell — a temporary environment on PATH
#+AUTHOR: Shape

Design only. No code lands with this file.

* Goal
Run a command with a set of packages on PATH without creating a generation
and without persisting anything. It is dev mode with a lifetime: the same
build, the same sources, an environment that vanishes with the process.

* Command shape and operands
=pm shell SPECS -- COMMAND [ARGS...]= — the spec directory, then =--=, then
the command to run with the packages on PATH. The spec directory is read
exactly as apply reads it, and =--lock= is accepted as it is for apply.
Reads: the spec directory, the sources, the lockfile when =--lock= is given.
Writes: a temporary prefix under the state root, removed on exit. No
generation, no store entry, no profile change.

* Area
=install/shell-env.rkt= — builds the specs into a throwaway prefix, assembles
PATH, runs the command through process/, and tears the prefix down. install
may reach build, process, store and machine, so this needs no new area. It
reuses dev-link, so the sources on PATH are the ones being edited.

* Refusals
- shell without =--confirm= refuses: even though nothing persists, a build
  runs code and writes a temporary tree, so the human gate applies.
- shell refuses an empty command after =--=, naming the usage.
- A non-zero exit from the command is reported, not swallowed; pm exits with
  the command's own code where it can.
- The temporary prefix is removed even when the command fails.

* Narration
- STEP "assemble" naming each package placed on PATH.
- WAIT before running the command, naming it, because the command blocks.
- STEP "teardown" naming the prefix removed.

* JSON output keys (fixed order)
=name=, =format=, =operands=, =packages=, =prefix=, =command=, =exit=.

* Open questions
- Is the temporary prefix under the state root or a system temp directory?
  The state root is the one place pm owns, so it belongs there.
- Does shell honour an interactive terminal, or is it non-interactive by
  design?

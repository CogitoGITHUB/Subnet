** One dispatcher, named stages, never numbers
# The gate is one Nushell script; every stage has a name that says what it checks.
- What PM does: =gate/check.nu= holds a STAGES table — [name, sub-stages, what it checks] — and =--list= prints it; the dispatcher validates against the same table, so the name exists in exactly one place. Sixteen numbered stages once made "what is stage 6?" cost a read every time; the table ended that. Sub-stages carry the full parent name (=text-lint/line-length=, =security-gate-lint/audited-writers=). Retired stages stay reachable by name and print the reason instead of a silent no-op.
- The rule: a stage is named by what it checks; selection, output and docs all read the same word.
- Verdict: REUSE.
- Read at: gate/check.nu header and STAGES table; HARD-RULES.org 3.7–3.8.

** text-lint: tabs, trailing space, line length, final newline
# The cheapest stage, and the one that keeps every file diffable.
- What PM does: four sub-rules over the whole tree; 102 columns; one file exempt by name with the reason in the file (=0.FOUNDATION.org=).
- The rule: formatting is not taste here — it is four facts a machine checks so review never discusses them.
- Verdict: REUSE.
- Read at: gate/check.nu (=text-lint= row, LENGTH_EXEMPT, MAX_LINE).

** read-check.rkt: the paren check that names the file and the line
# Never a hand-run paren count; the checker walks the open forms and prints their heads.
- What PM does: every named .rkt is read; the first malformed form is reported as =READ-BAD <file>:<line>=; on an unclosed form it also walks the raw text and prints the head of every form still open, so a head with nothing under it is obvious instead of four hundred lines away. Strings and =;= comments are skipped as the usual false positives.
- The rule: an unbalanced paren is NAMED, never guessed at; if the checker cannot cover a case, extend the checker.
- Verdict: REUSE.
- Read at: gate/read-check.rkt; AGENT.md ("Before editing any .rkt").

** one-way-dependency-lint: the architecture law, enforced
# The lint fails a NEW crossing; the known debt stays visible on every run.
- What PM does: every directory under src is an area; each line's cross-area require names its own target (=../AREA/file.rkt=), so no resolver is needed; the MAY_USE table transcribes ARCHITECTURE.org; 34 known crossings in 14 area-pairs are listed as visible debt (measured 2026-10-17) — deleting a pair is the fix, adding one should hurt.
- The rule: a new crossing fails the gate even while old debt is tolerated, because the debt is a recorded decision and the next one is a surprise.
- Verdict: REUSE — each new package transcribes its own area table.
- Read at: gate/one-way-dependency-lint.nu; plan/ARCHITECTURE.org.

** security-gate-lint: predicates called, writers audited
# A policy with no enforcer fails the gate.
- What PM does: every predicate =src/security/security.rkt= provides must be CALLED somewhere outside security.rkt itself (non-test), or the stage fails; the second sub-stage audits that effects happen only through the measured set of writers.
- The rule: "a predicate that is defined and never called is a contract with no enforcer."
- Verdict: REUSE.
- Read at: gate/check.nu (=security-gate-lint= row and its two sub-rules); package-manager/src/security/README.org.

** banned-words-lint and one-printer-lint: the law, made mechanical
# Two more examples of the same pattern: a written rule plus a stage that fails.
- What PM does: banned-words-lint enforces the naming law (see structure-and-naming-rules.org); one-printer-lint forbids raw output outside the one console printer (D-036). =obs-ok-lint= bans silent discards in .nu: bare ignore, bare try, do -i, /dev/null, timers.
- The rule: every law gets one stage or it is a wish; every silent path gets a lint.
- Verdict: REUSE.
- Read at: gate/check.nu rows for these stages.

** A gate that decides must be proven by a fixture that makes it fail
# The exit code comes from the same scope that computed it.
- What PM does: a gate once printed CHECK FAILED and exited 0 — the verdict left main through an environment write inside a =timeit { }= closure, and Nushell 0.116.1 discards env writes inside closures, so the exit read the default forever. The fix: the exit code comes from a value in the same scope that computed it; and a failing synthetic .rkt under =tmp= is the standing proof that the gate exits non-zero.
- The rule: a gate that decides anything is proved by a fixture that makes it fail; never through a side channel.
- Verdict: REUSE.
- Read at: docs/LESSONS.org (2026-10-10, first entry).

** Exit codes and usage
# README: 0 clean, 1 violations, 2 unknown stage, 3 wrong-nu.
- What PM does: =--changed= runs compile and tests over only what git says changed (the between-items gate); the full gate runs at phase boundaries; =need-nu.nu= refuses to run at all on anything but the pinned Nu (exit 3). The gate prints one line: version, files, failed, total, parked list.
- The rule: the gate's exit code is its verdict; everything else is commentary.
- Verdict: REUSE.
- Read at: gate/check.nu header; gate/need-nu.nu; HARD-RULES.org 4.6–4.7.

* 2a. Guix model inventory (from the in-vault Guix clone)
| Concept | Verdict | Reason |
|---------+---------+--------|
| package record | IMPROVE | keep shape; git-only source, exact-commit pins |
| origin uri/method/hash | IMPROVE | git URI plus commit only; id is the pin |
| inherit/variants | KEEP | composition without copy-paste |
| build-system + args + phases | KEEP | named steps plus order and insertion hooks |
| bags/gexp lowering | DROP | no derivations; backend runs commands |
| inputs/native/propagated | KEEP | deps vs build-time vs load-path; exact versions |
| outputs | DROP | one tree per package; no multi-output need |
| search-paths | LATER | system layout needs it; STEP 2 decides |
| supported-systems | DROP | conditionals cover the rest |
| replacement/grafts | DROP | explicit review-gated updates instead |
| properties alist | KEEP | open slot: triggers, smoke test, tracking policy |
| patches/snippets files | IMPROVE | git commits/branches plus build steps, no blobs |
| transformations CLI | IMPROVE | become spec fields (variants, tracking policy) |
| manifests/profiles/gens | IMPROVE | sets as specs in git; versioned dirs plus history |
| channels | IMPROVE | spec collections in git repos, no auth machinery |

* 2c. Beyond-Guix candidates judged against real needs
- Patches as git commits/branches: YES (case 7 needs it).
- Variants without copy-paste: YES (inherit layer; case 5 flavors).
- Conditionals (platform/feature/flags): YES (cases 5, 6).
- Optional features with conditional deps: YES (case 4 docs).
- Build steps as data, hooks, insertion points: YES (cases 5, 6).
- Per-package smoke tests: YES (a build that runs the result).
- Lazy-loading metadata: YES (deferred to STEP 2 design).
- Automatic provenance: YES (pin plus URL free from the vault).
- Spec collections in git (channels): YES. Profiles/sets as specs: YES.
- Docs embedded in spec: NO (summary only; prose lives in Org).
- Org as authoring format: NO (D-018; specs stay plain data).

* 2e. Updates and dev checkouts
Tracking per package: follow branch, latest tag by pattern, hold,
pinned-forever. Outdated means behind-count plus new tags. Danger:
pinned commit no longer an ancestor (rewrite), upstream moved or gone,
new submodules, changed build files. Updates replace installed code,
so the review gate is mandatory, never automatic.
Dev checkouts share vault objects (mechanism in STEP 4 design); local
no copy); local patches live as branches. PROPOSAL, still to confirm.

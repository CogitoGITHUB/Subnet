#+TITLE: users and declarations — one declaration per user
#+AUTHOR: Shape
# One job: one declaration per user over one shared content-addressed
# store, with per-user profiles. Status: planned only; nothing here is
# built, and no name here may be used by code until the register lists
# it (step 3). Source: =plan/FEATURE-users.org=;
# =plan/MOVE-ORDER.org= step 28.

* Purpose
- Everything today is one owner's. Step 28 gives each user their
  declaration and their profiles over one shared store, so two users
  on a machine stop sharing one owner's guesses.
* Name and location
- names: the feature's files are registered in step 3 before any is
  written; nothing is invented at build time
- code: touches =src/machine/= (user identity and paths), =src/spec/=
  (the declaration), =src/store/= (shared, content-addressed),
  =src/install/= (per-user profiles), =src/entry/= (the commands)
- area and layer: cross-cutting; each piece sits in its owning area and
  adds no new dependency direction
- may require: as each area already may
- may be required by: =entry=
* Public interface, in plain words
- a user declares their packages once; profiles are per user; the
  store is shared and content-addressed, so nothing duplicates and no
  user reads another's profile by accident.
* What it must never do
- Never trust ownership for reclaim: =profile-gc= computes
  reachability, and that is its own component.
- Never break the single-user case: one user keeps today's behaviour.
* Tests
- per area; one fixture with two users over one shared store.
* Docs it updates
- =plan/NAMING-REGISTER.org=; =plan/FEATURE-users.org= open questions;
  =plan/PROGRESS.org=.
* Depends on new components
- =profile-gc-cross-user= is its reclaim half: land them together.
* Build order
- =plan/MOVE-ORDER.org= step 28; before =profile-gc= can stop
  guessing.

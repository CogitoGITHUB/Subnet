#+TITLE: AIU EDITOR
# One job: what this program is and what it does today.
# Every line here is proved by a command that was run; the proof is in
# the tree: the gate, the feature table and the decisions.

* What it is

AIU EDITOR is a general editor first: plain text, keyboard driven, no
daemon, no legacy baggage. It grows out of the neomacs work, and it
hosts AIU-NOTATION later as one pluggable engine behind a contract
boundary, never a dependency.

The program has two halves:

  - the Rust crate under =editor/= — the hot path: the text state, the
    journal, and the wire.
  - the Racket package under =editor/src/= — the meaning side: the
    command table, the routing, the narration, the error records.

They meet in one place, the =join/= area, and the wire between them is
one line of JSON each way.

* Build

  cargo build --manifest-path editor/Cargo.toml --target-dir /tmp/editor-target

The binary lands at =/tmp/editor-target/debug/hot-path=. Nothing is
written inside the tree; the build leaves =editor/Cargo.lock= behind,
so delete it:

  rm -f editor/Cargo.lock

* Run a session

  cd "<the AIU EDITOR directory>"
  racket editor/src/entry/cli.rkt edit FILE

The path must be RELATIVE: the project directory holds a space, and
racket splits a path that holds one.

The session reads one command per line from the standard input and
prints every answer in the one printer. The commands are:

  insert TEXT   put the text at the end of the buffer
  type TEXT     put the text where the cursor stands
  save          write the buffer to the file and empty the journal
  show          answer the text as it stands
  journal       answer the journal's records
  replay        rebuild the state and answer what is waiting
  move-up       move the cursor up a line
  move-down     move the cursor down a line
  move-left     move the cursor left a character
  move-right    move the cursor right a character
  delete        take one character out, before the cursor
  select        turn the selection on where the cursor stands
  send          send what is selected to the agent
  help          answer the names in the table
  quit          end the session

A real run:

  (ev-open the editor editing /tmp/readme-demo.txt 2026-10-20T08:21:56Z ...)
  bytes=22 file=/tmp/readme-demo.txt lines=1 pending=0
  bytes=30 lines=1 pending=1
  count=1 records=insert one line
  bytes=30 file=/tmp/readme-demo.txt lines=1 pending=0
  bytes=30 lines=1 text=hello from the read meone line
  bye

The numbers are: the bytes and the lines of the text, and =pending= — the
records in the journal, the edits that are not saved yet.

The **cursor** is a point in the text, and it moves: =move-left= and
=move-right= a character, =move-up= and =move-down= a line, and =type=
puts text where it stands. A session that typed at the cursor:

  type hello world
  move-left
  move-left
  type X

leaves =hello worXld= — the X landed where the cursor stood. The
journal records the place of every edit (=insert-at 14 and the second=),
so the state comes back exactly after a kill.

* The journal, and what a kill costs

The state between two commands is the file plus the journal: the saved
text lives in the file, the unsaved work lives in the journal. So a
crash, a kill or a closed terminal costs nothing.

The journal sits beside the state, one file per edited file:

  ~/.local/state/aiu-editor/journal/<name>-<key>.journal

A =save= writes the file and empties the journal. A session that is
killed with =kill -9= mid-edit leaves the edit in the journal, and the
next session on the same file brings the state back exactly.

* The routing: which layer sees a key first

The keyboard layer owns the routes, and the shape is the contract's: the
focused program sees a key first, then the editor's own layers, and the
multiplexer's reserved prefix applies everywhere.

  racket editor/src/entry/cli.rkt routes

prints the walk — one line per key, the layer that saw it and what it
meant there:

  layer: normal  program claims: none  reserved prefix: C-b
  C-b -> multiplexer -
  C-s -> editor save
  C-q -> editor quit
  C-l -> editor show
  C-h -> editor help

=C-b= is the reserved prefix: the multiplexer keeps it for its own
actions, it applies everywhere, and no layer of the editor may bind it.
The choice and its reason are in =decisions/reserved-prefix.org=.

The tables are data, not code: =editor/src/routes/keymaps.rkt= holds the
layers and their keys, and a route names a command from the command
table, never a function. A key is named the way the terminal names it:
=C-= for control, =M-= for alt, =S-= for shift, and a word for a named
key — escape, return, tab, space, backspace, delete, up, down, left,
right, home, end, pageup, pagedown.

* The tasks: declare, list, run, sequence

A task is a plain function on the meaning side: it takes the session and
the string arguments, and answers one line. Its doc line is the comment
block above its own definition, so the list and the help come from the
source and never from a second list.

  racket editor/src/entry/cli.rkt tasks

lists the table:

  insert — insert puts the words into the buffer and journals the edit. In the dry-run scope it prints what it would do and changes nothing.
  say — say prints the words it was given as one line, and changes nothing.

and a task runs against a file:

  racket editor/src/entry/cli.rkt task FILE NAME WORDS...

  racket editor/src/entry/cli.rkt task /tmp/tasks-demo.txt say hello the task runner
  hello the task runner

A =--= between two runs makes a sequence, and the runs go in the order
they were given:

  racket editor/src/entry/cli.rkt task FILE say first run -- insert a real line -- say second run
  first run
  bytes=41 lines=1 pending=1
  second run

=--dry-run= opens the scope where a task that acts prints what it would
do and changes nothing — the file and the journal stay untouched:

  racket editor/src/entry/cli.rkt task --dry-run FILE insert a line that must not land
  would insert: a line that must not land

A name the table does not hold is refused by name, never guessed at:
=there is no task named nosuchtask; ask for one of: insert, say=.

* The dashboard: the placeable pieces

The dashboard is the status and the context display. The placement is
**data**: a piece names an edge, a width and an order, so any piece can
go on any edge and several pieces can share one.

  racket editor/src/entry/cli.rkt dashboard FILE

draws the screen, one line per row:

  /tmp/tasks-demo.txt  1 lines  41 bytes  1 pending
  layer normal  agent idle -
  normal C-s -> save
  normal C-q -> quit
  normal C-l -> show
  normal C-h -> help

A piece is never cut: a piece whose text needs more room than its size
says gets the room it needs, so the same piece fits any edge. The same
piece was placed on all five edges — top, bottom, left, right and
floating — and every one of them put it where it was asked.

The meaning is Racket and the drawing is Rust; the two meet in the join
area. The gate's eighth stage, `dashboard-check.rkt`, checks that every
piece of the placeable piece list is really drawn, and it fails on a
piece welded to an edge the drawing does not know.

* The keyboard: the bytes of a key become its name

The keyboard is split the way D-007 says: the **decoding is Rust** (the
input area) and the **keymaps and the meaning stay in Racket** (the
routes area).

  racket editor/src/entry/cli.rkt keys normal 13 11 1b5b41 61 1b

answers the name of each key, the layer that saw it and the command it
runs:

  C-s -> normal save
  C-q -> normal quit
  up -> unclaimed -
  a -> unclaimed -
  escape -> unclaimed -

The bytes are given as hex, because a key may be any byte at all. The
hot path also answers the way back — how a key name is spelled — and the
gate's `key-check.rkt` stage walks every key of the keymaps round: the
name that comes back must be the name that went in.

The kitty keyboard protocol is **adopted, not invented**: the flags that
ask the terminal to report the escape codes it would otherwise swallow
are the protocol's own, and the reader uses no timer of its own. A lone
escape is the escape key, and the next byte decides it.

* The gate

  nu gate/check.nu

Nine stages, and a green run ends:

  stages that checked nothing: 1 of 9
  light gate: green, 9 stages ran

  paren-check     every Racket file reads
  naming          no banned word in any name
  one-way         a require may point downward only
  security-gate   every security rule answers as it says
  language-split  only join/ may cross between Rust and Racket
  comment-lint    every file has a header and every definition a comment
  route-check     the reserved prefix is bound by no layer, and every
                  route names a command that exists
  key-check       the decoder and the keymaps agree on every key
  dashboard-check every piece of the placeable piece list is really drawn

The route check is the seventh stage, and it was proved on a copy with
both faults planted: it named the layer and the key that took the
prefix, and the route that named a command the table does not hold.

The security stage prints NOTHING-TO-CHECK: the security area does not
exist yet, and the gate says so instead of passing silently.

* The area law

The areas, lowest first:

  errors  narration  machine  security  join  devloop  journal  buffer
  notation  commands  routes  input  drawing  models  dashboard  send
  picker  checkpoint  audit  entry

=errors= is the floor and =entry= the ceiling, and a require may point
DOWNWARD only. Rust owns the hot path — =input/=, =drawing/=, =journal/=
and the buffer's text; Racket owns the meaning side — commands, routes,
models, rules and config. The seam is =join/=, and the one-way lint and
the language-split lint keep every other area clean.

* How it is put together

  editor/src/errors/      the error record, the one raise, the render
  editor/src/narration/   the events, the voice, the wait door, the printer
  editor/src/machine/     the HOME seam, the locks, the cancel door
  editor/src/join/        the wire: the request, the answer, the transport
  editor/src/journal/     the record of every edit, and the replay
  editor/src/buffer/      the text state: bytes, lines, offsets
  editor/src/commands/    the command table: one name, one function
  editor/src/routes/      the routing: which layer sees a key first
  editor/src/entry/       argv, the dispatch, the session

The wire between the two halves is one line of JSON each way, and it
travels through a PAIR OF FILES — one for the request and one for the
answer. That is a fact of this Racket build and not a choice:
=racket/system= hands a child =/dev/null= for every stream that is not a
file stream. The decision is D-008 in the root DECISIONS.org.

* What is not there yet

  - The input is read on the RACKET side, one typed line at a time. The
    =input/= area, with the keys read in Rust, lands when a stream can
    carry them; =decisions/plain-text-slice.org= says what it costs and
    what it takes to undo.
  - The multiplexer has no code, so the editor's half of the routing is
    all that can be built here. The walk that runs with the editor in a
    pane is still owed.
  - The =security= area does not exist, so the gate's security stage has
    nothing to check.
  - The =notation= seam, the =drawing= area, the dashboard, the agent
    boundary, the kit — none of them are built.
  - The root D-number for the reserved prefix is still owed: the root
    decision log is read-only from this project.
  - Nothing is long-lived. Every command is a one-shot call to the hot
    path, and the state lives in the file and the journal.

* Rules for anyone working here

  - Register a name in =plan/package-tree.org= before you use it.
  - One file, one job. Every file opens with a header comment that says
    what it is; every top-level definition has a comment line directly
    above it. The comment-lint stage checks this.
  - A require may point downward only.
  - Commit with explicit relative paths. Never =git add -A=.
  - Nothing writes outside =/tmp= and the state directory.
  - No test files in the tree (root DECISIONS.org D-001). A check that
    proves something is a stage of the gate, and a check that tries to
    fail is proved on a copy in =/tmp=.
  - Never weaken a check. A check that cannot fail is not a check.

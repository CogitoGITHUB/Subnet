#+TITLE: Package tree — AIU NOTATION
# One job: the package directory, the area law, and every planned directory and file with its single job
# Status: planned 2026-10-17; this file is the register for the package — a name that is not here does not exist yet.

* The package directory
# one subdir holds the whole package; nothing is scattered.
  - The package is =notation/=, directly under this project directory.
    Everything a run needs lives inside it; the project root keeps only
    context and docs plus gate/, tools/ and agent/ — the same split as
    PM, where =AIU-PM/package-manager/= holds the code and the repo
    root holds the rest.
  - =notation/INDEX.org= is created with the directory and lists every
    dir and file below, one job each; every subdirectory carries its
    own INDEX.org (PM calls these README.org; we use the ecosystem's
    one index name for every directory).
  - Nothing of the package lives outside =notation/=: no src/ at the
    project root, no stray scripts.

* The law
# areas lowest first; dependencies point one way; the language seam is named.
  - Areas, lowest first; a require may point downward only. The gate's
    one-way lint transcribes this table, and it is the source for it:
    errors, narration, machine, security, join, text, parser,
    elements, model, diagnostics, references, literate, generation,
    rendering, surface, entry.
  - errors is the floor (everything may use it; it uses nothing);
    entry is the ceiling (it may use everything; nothing uses it).
  - Rule 09, named exactly: Rust owns the hot path — =text/=,
    =parser/= and =rendering/= (input, drawing, layout, parsing,
    terminal handling). Racket owns the meaning side — element names,
    the model, rules, documents. The seam is =join/=: the only place
    the two languages meet, holding how the meaning side loads in the
    baked binary that loads nothing at startup.
    =gate/language-split-lint.nu= keeps every other area clean.
  - One file, one job; the reader test on every name; banned words as
    in the ecosystem law (no core/, engine/, utils/, manager/,
    handler/, tmp/).

* The crate
# minimal on purpose: one crate, no workspace, no dependencies.
  - =src/main.rs= — the three commands, one small binary: =parse= prints the
    payload document, =render= prints the plain render, =roundtrip= says
    whether the tree prints back to identical bytes. Each takes one file path.
    The binary is the by-hand run's Rust side; nothing is automatic yet.
  - =Cargo.toml= — the crate manifest for the package: one crate named
    notation, no workspace, no dependencies.
  - =src/lib.rs= — the module list: which area files belong to the crate. It
    uses =#[path]= so every area file lives exactly where the tree lists it
    and no per-area module file is invented.

* Names registered
# one line per name: the name, then what it is for. Registered here before
# any file uses it; a name not in this list does not exist yet.
  - =stray-text= — the error name for text found outside any named block:
    severity error, no off switch, the text kept untouched and the rest of
    the file still parsed. Carried by the parser as an error node.
  - =mismatched-end= — the error name for an end line that does not match the
    innermost open block; it names the line where that block was opened.
  - =unclosed-block= — the error name for a block still open at the end of the
    file; it names the line where the block was opened.
  - =unknown-block-name= — the error name for a start or end line whose name is
    not one of the Tier 1 block names.
  - =missing-title= — the error name for a file whose first block is not a
    title, or which has no title block at all.
  - Tier 1 block names: =title=, =paragraph=, =code= — the only names a start
    or end line may carry in Tier 1.
  - Declaration keywords: =tags=, =language=, =style=, =theme=, =color=,
    =format=, =font= — the only "keyword: value" lines a block may declare;
    they are stored as hints, never as meaning.
  - =check= — the CLI command that reads a file, lists every error with its
    line number and exits non-zero when any error is found; the same
    documents the editor receives through the boundary.
  - =syntax/first-run-output.org= — the captured output of the one by-hand run
    allowed for items 2 and 3, with its timings and its failures named.
    Registered 2026-10-17.
- =syntax/example.notation= — the real sample page the first by-hand run
    reads: a title with tags, two paragraphs, and a code block whose body holds
    a line that looks like a start line. Registered 2026-10-17.
- =.notation= — **provisional** file extension for a notation page, registered
    2026-10-17 for the first slice only. It is provisional because no owner
    decision has fixed the extension; a page may be read with any name today,
    and the parser does not care what a file is called.
  - =parse-tree-document= — the payload the Rust parser prints and the Racket
    side reads: one plain text document in one frozen shape, with no Racket
    dependency on the Rust side. Its shape is written in words in
    =join/INDEX.org=; how the document is carried — a call or a subprocess —
    is still open and is not decided here.

* What starts first
# the first files, tied to the build order.
  - Lands first, with the light gate: errors, narration, machine and
    the =notation/= INDEX.org — the floor every later file stands on.
  - The first slice (build-order steps 1–2): text/, parser/, elements/,
    model/, rendering/plain.rs and entry/cli.rkt — a page with a title
    and paragraphs parses, renders and re-parses agreeing.
  - The mark is decided and was revised the same day: NOTATION D-014 REVISED
    2026-10-17: start/end keywords, everything inside a block (owner; the root
    =DECISIONS.org= record is pending, carried in ROOT-REQUEST-D014.org).
    Nothing waits for that record — TODO item 1 lands this tree and the
    floor first, and item 2 writes the first elements with the mark while
    block bodies stay opaque to the parser (history: before 2026-10-17 this
    line said "Until then nothing of =notation/= exists and this file is the
    whole plan", which contradicted item 1 and is gone; revised the same day
    it read "the mark is decided: { }").

* Absent on purpose
# what similar programs carry and this one will not.
  - No engine/, core/, utils/ or any description-name directory; the
    word "engine" stays a description in the docs, never a path.
  - No math, graphs or advanced-syntax areas: tier 3, opened only by
    the owner (checklist/tier-3/).
  - No editor features; the editor is its own package (rule 14).

#+TITLE: Kit entry
# One job: the kit entry PM ships: what it declares about PM's own capabilities
# Status: filled 2026-10-16; planned only, PM itself is not touched here.

* What PM must gain
# the capability in words; the exact PM files are named only after PM is read, until then say where to look later.
  - One machine-readable declaration — PM's kit entry — naming PM's
    commands (name, arity, mutating or not), the JSON envelope version,
    where the event feed lives, which sight files PM writes, and which
    kit surfaces PM ships.
  - The skill file PM owes: the learned notes record PM's MCP server and
    OpenCode plugin as shipped and the skill as owed; the skill is built
    from this declared table so its examples cannot drift.
  - The entry is derived from what PM already enforces — its command
    table and the gate that checks discovery against enforcement — made
    visible in one place, not invented separately.

* Shape
# how the entry, surface or file looks from the outside. No code.
  - A small declaration shipped beside PM's documents: commands in fixed
    key order, each marked read or mutate; one line per kit file; the
    feed path and the sight-file directory.
  - The same shape as the ecosystem kit (agents/agent-integration-kit.org):
    a declaration, then the checklist PM's kit must pass.
  - Readers: the skill builder, the plugin, the MCP server and PM's own
    gate — all read this one declaration; none keeps a private copy.

* Proof that it works
# the one check that shows this is done when the PM prompt runs.
  - A gate stage fails when the declared table and the enforced command
    set disagree — the agree-check PM already applies to its discovery
    table, extended to every kit file; break one entry on purpose and the
    gate goes red.

* Owed to the PM checklist
# one line per PM change, added to pm-change-checklist.org.
  - Ship the kit entry and the owed skill file; extend the agree-check to
    cover both.

#+TITLE: Live agent audit and checkpoints
# One job: seeing agent changes as they happen, and the git checkpoint before agent actions
# Status: filled 2026-10-16; recommendations await owner review.

* The questions
# the questions this file must answer, listed before any option is weighed.
  - How does the human see an agent's changes as they happen, with no
    polling?
  - Where does that view come from — the agent's own events, or the work
    tree itself?
  - What protects the work before an agent starts mutating, and how is it
    reversed?

* Options
# two or three real options, each with what it costs and what it gives.
  - Option A — watch the work tree with inotify events and narrate what
    arrives through the one event feed. Cost: inotify cannot say which
    process wrote; attribution needs our own bookkeeping, stated
    honestly. Gain: agent-neutral ground truth, one watch for any agent;
    coalescing and overflow are already understood — re-read state, rescan
    on overflow, nothing missed silently.
  - Option B — hook each agent's own event stream. Cost: per-agent work;
    an agent's plugin surface becomes load-bearing; the other adapter gets
    nothing. Gain: richer events, where an agent offers them.
  - Option C — poll and diff. Cost: forbidden — no timers, no polling; a
    timer is a guess about when something finishes. Gain: none.

* Recommendation
# one recommendation, named plainly, with its reason.
  A for seeing, with B allowed only as an addition where an agent's stream
  is already free. For protecting: a git checkpoint at session start,
  before any mutation can land — a dangling commit held by a dedicated
  ref, named for the session, never touching the branch; rollback restores
  from the ref; pruning is a separate, explicit command, never automatic.
  This copies PM's proven verdicts (learned/versioning-and-rollback.org):
  fail closed — the old state survives every failure path — and
  generations are never pruned by a sweeper.

* What it needs from the package manager
# anything this design needs from PM, marked for the later PM prompt.
  - Nothing new to build; the pattern is PM's, copied here so adapters and
    the contract reuse it as the learned file promises.

* Open decisions
# what remains undecided and who decides it.
  - inotify under proot on Android: syscall translation may affect
    watches — a device test is owed before this is promised — owner.
  - The checkpoint ref's location and naming — contract step 9.
  - The trigger point: session start is cheaper and more predictable than
    first seen write; confirm at the freeze — owner.

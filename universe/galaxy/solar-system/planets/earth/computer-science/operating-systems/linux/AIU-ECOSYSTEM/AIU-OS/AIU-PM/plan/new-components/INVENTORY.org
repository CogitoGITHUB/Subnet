* Group (b): the ecosystem plan, ../../pm-integration/

- Hermes integration — PM from Hermes: skill or plugin, and what each
  action looks like (hermes-integration.org). Every project ships its
  agent surfaces; PM's Hermes side has no entry at all.
- install-then-bake — how a PM install feeds a program's dev-mode bake
  (install-then-bake.org). Without it, dev mode cannot consume a package
  PM installed, which is the first thing a developer tries.
- adapter versioning and rollback — versions and rollbacks for the agent
  adapters and the contract itself (adapter-versioning-and-rollback.org).
  An adapter that cannot be rolled back pins the contract to its worst
  version forever.
- MCP surface additions — search, install, status, build, bake
  (mcp-surface.org). The six verbs stop at activation; the ecosystem
  plan promises five more, and an agent can only call what is exposed.
- kit entry — what PM declares about its own capabilities (kit-entry.org).
  The kit entry is how other projects discover what PM can do at all.
- context-bundle senders — sending a package, a plan or a failure to an
  agent as a context bundle (context-bundle-senders.org). A failure an
  agent cannot read is a failure the agent will repeat.
- AI-sight files — the files PM writes so an agent reads PM state
  directly (ai-sight-files.org). Reading state from files beats parsing
  narration: it is stable, cheap, and needs no heartbeat.

* Group (d): the remaining MOVE-ORDER features, each with a plan file

- =pm doctor= (step 23) — a read-only health check, area
  =entry/doctor-report.rkt=, per =plan/FEATURE-doctor.org=. Missing
  because PM cannot say what is wrong without changing anything.
- =pm export= / =pm import= (step 24) — portable bundles, areas
  =store/bundle-format.rkt=, =install/export-profile.rkt=,
  =install/import-profile.rkt=, per =plan/FEATURE-export-import.org=.
  A machine can be set up today but never reproduced elsewhere.
- binary cache (step 25) — build once and reuse by content hash, areas
  =store/content-address.rkt= and =build/build-cache.rkt=, per
  =plan/FEATURE-binary-cache.org=. Every machine rebuilds what another
  machine already built.
- =pm search= / =pm info= (step 26) — browse and show one, areas
  =entry/search-report.rkt= and =entry/info-report.rkt=, per
  =plan/FEATURE-search-info.org=. Asking today means reading the store
  by hand.
- =pm shell SPECS= (step 27) — a temporary environment on PATH, nothing
  persisted, area =install/shell-env.rkt=, per =plan/FEATURE-shell.org=.
  Trying a package without installing it is impossible today.
- users and declarations (step 28) — one declaration per user, one
  shared content-addressed store, per-user profiles, per
  =plan/FEATURE-users.org=. Everything today is one owner's, and
  =profile-gc= already has to guess about other users.
- =pm config= and completions (step 29) — per
  =plan/FEATURE-config-and-completions.org=. Settings have no home and
  the shell has nothing to complete from.

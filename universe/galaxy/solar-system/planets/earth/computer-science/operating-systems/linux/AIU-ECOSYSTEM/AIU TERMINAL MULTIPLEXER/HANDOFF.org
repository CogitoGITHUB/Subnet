* What this program is
# Shells, panes, a layout tree, and a session holder with detach and reattach.
  - The holder owns the shells and the screen is a thin client; Nushell command records are first class.
  - Terminals are a facade over tty; what the phone cannot promise is written down, never assumed.

  - Base complete; the ready-up closed the decisions: the route (D-002), herdr as the tested candidate (D-003), the control surface (D-004), the shared key-routing handover (D-005) and the log shape (D-006); plan/open-decisions.org is a redirect stub.
  - The TREE LANDED (=5a8908e7=): the package is =multiplexer/= with the floor areas =errors/=, =narration/= and =machine/=, and the gate is green at 7 stages (the security gate prints NOTHING-TO-CHECK until that area exists). Every module really loads.
  - The ROUTE IS DECIDED (=937a2c9e=): this phone builds Rust — a tiny binary builds in 7.9 s, starts in 23 ms, and a pty works here (=/dev/pts/N=). The numbers are in =research/tiny-binary-probe.org=; the holder is therefore written and built on this phone, with herdr kept behind the same contract as the fallback.
  - THE HOLDER WORKS (=abab3340=): a shell on a pty in a session that outlives every client, an append-only log flushed per record, and a unix socket in the session's state directory. The client is a thin screen. The phone proof is =tools/holder-probe/probe.nu=: after the detach the shell was still alive and still writing to the log, and a second client found the same session and the same shell. What the phone cannot do is recorded, not promised: the holder dies with the session that started it, so the promise is about the DETACH.
  - THE AGENT SURFACE WORKS (=88ce654c=): the MCP server over stdio talks to a holder's socket, so an OpenCode agent can list the sessions, read a session's records and send to a session's shell. Reading is free; a send needs the human's token and the server checks the token itself. The proof is =tools/mcp-probe/probe.nu=. On this phone both this program's server and the editor's are registered in OpenCode (=opencode mcp list= shows them connected) and both skills are installed, so an OpenCode session drives the multiplexer and the editor without the owner touching the terminal.
  - THE PANES LANDED (=b9541c94=): a layout file names the panes a session holds, each pane is a shell with a name, and every record carries the pane's name. A send is aimed at a pane by name. The proof is =tools/panes-probe/probe.nu=. What is not there yet is the DRAWING: the panes side by side on one terminal, which is the next slice of item 5 and the ground the key routing needs.
  - The owner's third addition of 2026-10-21: in the tm, one key opens OpenCode with the context of the pane the owner is in — the shell output, the shell, the place and the why — and nothing is copied by hand. The design is =plan/agent-opens-here.org=; it waits on the panes, the key routing and select-and-send.
  - The owner switched the priority on 2026-10-21: this program is built FIRST, and the AIU-PM and the AIU EDITOR implementation are paused until it works. Both say so in their own README and TODO.
  - README.org now says what this program is and what works today.

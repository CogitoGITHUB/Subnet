* What it is

AIU NOTATION is the text format of the AIU ecosystem.
A page is a plain text file with the extension =.aiu=.

The program has two halves:

  - the Rust crate under =notation/= — the engine: it parses, renders
    and round-trips a page, fast.
  - the Racket package under =notation/src/= — the model: it reads the
    engine's document, answers questions about a page and writes the
    engine's output back out.

Both halves are built and green today.

* The hard rule

A block is three lines:

  =<name> start=
  the content, on its own line or lines
  =<name> end=

The keyword comes FIRST both times.

  title start
  tags: sample
  The first sample page
  title end

=end title= is the RETIRED spelling. It closes nothing and is
ordinary text.

The owner chose this because it reads the same way to everyone who
reads these files — a person, an AI, a =grep=, a CLI. The name is the
subject of the line and the word after it says what the line does, so
the eye always lands on the same word in the same place.

* The names you may use

Block names (the word on a start or end line):

  title  paragraph  code  heading  table  header  row  comment

Declaration keywords (the word before the colon on a line):

  tags  language  style  theme  color  format  font  level
  caption  column  cell  row-id  meta  todo

A line whose word is NOT in that list stays plain content. A
=colour: blue= line is not a declaration; it is text.

* Build

The crate builds with:

  cargo build --manifest-path notation/Cargo.toml --target-dir /tmp/notation-target

The binary lands at =/tmp/notation-target/debug/notation=.
The build leaves =notation/Cargo.lock= behind; delete it:

  rm -f notation/Cargo.lock

Nothing is ever written inside the project tree.

* The engine, four commands and a fifth

  notation parse FILE       prints the parse tree document; the
                            time it took goes to stderr as =parse-ms: N=
  notation render FILE      prints the plain render: the content of
                            the page, with the marks, the declaration
                            lines and the comments dropped
  notation render-rich FILE prints the same content drawn with
                            unicode: a =═= rule under a title, a box
                            around a code block, two columns of indent
                            per nesting level, a =✗ line N= mark on an
                            error
  notation roundtrip FILE   says whether the page prints back to the
                            very same bytes
  notation todos FILE       lists every todo in the page

* The daily script

One script does the everyday work:

  nu tools/aiu.nu check     FILE
  nu tools/aiu.nu render    FILE
  nu tools/aiu.nu roundtrip FILE
  nu tools/aiu.nu json      FILE
  nu tools/aiu.nu from-json FILE.json

It builds the binary if it is missing, and it never writes in the
tree. =json= prints the page as JSON; =from-json= prints a JSON file
back as a =.aiu= page.

* The model, from the shell

  cd "<the project directory>"
  /root/home/shape/opt/racket-full/bin/racket notation/src/entry/cli.rkt check FILE

Use a RELATIVE path. The project directory holds a space, and racket
splits a path that holds one, so an absolute path fails.

The commands are =check=, =literate=, =send=, =json= and =from-json=.
The exit codes are named: =exit-clean 0=, =exit-findings 1=,
=exit-refused 2=.

=check= reads a PARSE TREE DOCUMENT — the output of =notation parse= —
not a page. =tools/aiu.nu= does both steps for you.

* The parse tree document

The frozen shape, in =notation/src/join/INDEX.org=:

  NOTATION-DOCUMENT 1
  file "<path>"
  node block <name> <startLine> <startOffset> <endLine> <endOffset> <depth>
  decl <keyword> "<value>" <line> <offset>
  error <kind> <line> <offset> <openerLine> "<what>" "<whatToDo>"
  end

A quoted field is ONE field and keeps its spaces. A double quote
inside is written twice. The =depth= field says what sits inside what,
so a reader never has to count.

* What the model answers

  read-outline      the document as a tree
  address-of        a node's address: =title:title@1=; an error node
                    is =error:<kind>@<line>=
  addresses         every address, in tree order
  property-of       a declaration's value on a node
  tags-of           the tags of a node
  heading-numbers   the computed number of every heading
  collect-findings  the findings of a document
  build-report      the report and its exit code
  surface-answers   the answers document for the editor
  read-notices      the notices document

* What a diagnostic looks like

  (struct finding (kind who line column what what-to-do) #:transparent)

The kinds are =unknown-element-name=, =tag-names-nothing=,
=property-no-value=, =link-no-target= and =parser-recovery=.

A report line reads:

  ERR err-stray.aiu at line 4, column unknown: parser-recovery: the
  parser recovered from stray-text: text outside any named block; what
  to do: put the text inside a "<name> start" / "<name> end" block

The column says "unknown" because a parse tree document carries no
page. The engine's own error line carries the line, the byte and the
line the block was opened at.

* The six errors the engine names

  stray-text         text outside any named block
  mismatched-end     a close that does not match the open block; it
                     names the block and the line it was opened at
  unclosed-block     a block that was opened and never closed; it
                     names the line it was opened at
  unknown-block-name a name that is not registered
  missing-title      a file whose first block is not a title
  bad-heading-level  a =level:= that is not a whole number of 1 or
                     more

* Headings and their numbers

A heading takes its depth from a =level:= declaration; without one it
is level 1. The NUMBER is computed and never written by you:

  1        1.1        1.1.1        1.2        2

Both halves compute the same numbers: the Rust engine for the render,
the Racket model for the document.

* Tables

A table holds a =header= block and =row= blocks:

  table start
  caption: Prices
  column: name text
  column: price number
  column: note text optional
  header start
  cell: name
  cell: price
  cell: note
  header end
  row start
  row-id: r1
  cell: Widget
  cell: 9.99
  cell:
  row end
  table end

A =column:= line names the column, its type and whether it is
optional. The types are =text=, =number=, =integer=, =bool=, =date=
and =json=. An EMPTY =cell:= is a MISSING value, and a missing value
is allowed only in an =optional= column.

A table is read, checked, and drawn two ways: as HTML and as LaTeX.
The structure is kept apart from the drawing.

* JSON, both ways

A page becomes a JSON array with one object per top-level block:

  [ { "title": "..." },
    { "paragraph": "..." },
    { "heading": { "level": 2, "number": "1.1", "text": "..." } },
    { "table": { "caption": "...",
                 "columns": [ {"name": "price", "type": "number",
                               "optional": false} ],
                 "header": [ ["name", true] ],
                 "rows": [ {"id": "r1",
                            "cells": [ ["Widget", true], ["", false] ] } ] } },
    { "code": "..." },
    { "data": <any JSON value> } ]

The =data= key is the way out for machine-oriented data the notation
has no block for. A JSON file read back becomes a =.aiu= page, and
the two JSON texts come out the same.

What JSON cannot hold is said out loud: a comment, a blank line, and
the way a heading was numbered all come back changed or not at all.

* The todo state

A todo is a line that starts with =todo:=. It may sit on ANY block —
a title, a paragraph, a heading, a table, a code block — and it may
sit inside a comment. The only place it is not read is the body of a
code block, because a code body is not read as notation.

  notation todos FILE

lists them, one per line, with the line each sits on.

* The gate

  nu gate/check.nu

Seven stages, and a green run ends:

  stages that checked nothing: 0 of 7
  light gate: green, 7 stages ran

  paren-check     every .rkt file reads
  naming          no banned word in any name
  one-way         a require may point downward only
  security-gate   every security rule answers as it says
  language-split  only join/ may cross between Rust and Racket
  load-check      every module loads
  comment-lint    every file has a header and every definition a
                  comment above it

The security gate probes the seven security rules — a target that
names no file, a target that is a directory, a target that climbs out
with "..", an absolute target, a target that is the document itself,
an unwritable place, and a declaration no rule registers read out of a
code body — on a value that must be refused and on one that must pass.
It also names, for each rule, the files that call it. TODAY NO FILE
CALLS THEM YET, and the gate says so on every run.

* How fast it is

  parse, 20 lines        0 ms
  parse, 2000 lines      40 ms
  the whole check        about 18 s, on 20 lines AND on 2000 lines
  =racket -n -e ''=      about 0.5 s
  loading one module     about 11 s
  loading the CLI        about 23 s

The check costs the SAME on a small page and on a big one, so the
cost is the MODULE LOAD on this phone, not the page. The engine
itself is instant.

* What is not there yet

  - The Racket =check= command reads a parse tree document, not a
    page. The engine makes the document; =tools/aiu.nu= does both.
  - A path that holds a space cannot be handed to racket, so every
    Racket command needs a relative path.
  - The seven security rules have NO caller. The literate and the
    generation areas still raise their own refusals.
  - The =link= keyword is not registered, and the =references= area
    holds no files.
  - The kit — the MCP server, the skill, the plugin — is not built.
  - There are two address shapes: the model says =title:title@1= and
    the surface answers say ="title/1"=. One of them has to go; the
    hand-off asks for one.
  - Nothing is long-lived. Every command is a one-shot process.

* Rules for anyone working here

  - Register a name in =plan/package-tree.org= before you use it.
  - One file, one job.
  - Every file opens with a header comment that says what it is, why
    it exists and who calls it. Every top-level definition has a
    comment line directly above it. The =comment-lint= stage checks
    this.
  - Commit with explicit relative paths. Never =git add -A=.
  - Nothing writes outside =/tmp=.
  - No test files in the tree (root DECISIONS.org D-001). The owner
    lifted that on 2026-10-19 for one verification run, and those
    commands live in =/tmp=, never in the tree.

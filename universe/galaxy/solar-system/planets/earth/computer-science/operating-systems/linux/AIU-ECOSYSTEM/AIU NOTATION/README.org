* What it is
# the short answer, from HANDOFF.org and rule 12.
  - The owner's own file format and syntax in one: it replaces Org, Markdown
    and LaTeX for their everyday use.
  - Plain text is the source of truth; a rendering engine shows it live.
  - A page is a plain text file with the extension =.aiu=.
  - The product name is AIU-NOTATION. The program is separate and the code
    lives in one package directory, =notation/=.

* The hard rule
# the one rule everything else obeys. The owner chose it.
  - A block is three lines: the name and =start=, the content on its own line
    or lines, then the name and =end= again.
  - So a block reads:
    #+begin_example
    title start
    tags: sample
    The first sample page
    title end
    #+end_example
  - The keyword comes FIRST both times: =<name> start= and =<name> end=.
  - The retired spelling =end <name>= closes nothing. It is content like any
    other line, so a file written the old way reports a stray text instead of
    silently closing a block.
  - WHY the owner chose it: "I chose it so it is easy to read for everyone —
    humans, AI, grep, CLI tools." The name is the subject of the line and the
    word after it says what the line does, so the eye always lands on the same
    word in the same place.
  - A code block's body is opaque: only =code end= closes it, and any line in
    between that looks like =title start= is content and opens nothing.

* Build
# the one command, and the one file it leaves behind.
  - =cargo build --manifest-path notation/Cargo.toml --target-dir /tmp/notation-target=
  - The build leaves =notation/Cargo.lock= behind. Delete it:
    =rm -f notation/Cargo.lock=
  - The binary lands at =/tmp/notation-target/debug/notation=.
  - Nothing is written inside the project tree.

* Run
# four commands, one file path each.
  - =notation parse <file.aiu>= — prints the parse tree document, and the parse
    time in milliseconds on the error port.
  - =notation render <file.aiu>= — prints the plain render: the marks and the
    declaration lines are hidden, the content is kept.
  - =notation render-rich <file.aiu>= — the same content drawn with unicode: a
    heading rule, a code box, an indent per nesting level.
  - =notation roundtrip <file.aiu>= — prints "roundtrip: identical (N bytes)"
    when the tree prints back to the identical bytes, and exits 1 when it does
    not.

* Check
# the daily script, and the gate under it.
  - The daily script does the whole thing:
    =nu tools/aiu.nu check <file.aiu>=,
    =nu tools/aiu.nu render <file.aiu>=,
    =nu tools/aiu.nu roundtrip <file.aiu>=,
    =nu tools/aiu.nu json <file.aiu>= and
    =nu tools/aiu.nu from-json <file.json>=.
  - It builds the binary if the binary is missing, and it never writes inside
    the project tree.
  - The gate is the whole project: =nu gate/check.nu=. It has seven stages:
    paren-check, naming, one-way, security-gate, language-split, load-check
    and comment-lint. A green run ends with "light gate: green, 7 stages ran".
  - A stage with nothing to check prints NOTHING-TO-CHECK and never PASS.
  - The Racket check command on its own must be run with a RELATIVE path:
    =racket notation/src/entry/cli.rkt check <document>=. The absolute path of
    this project holds a space, and racket splits its argument on that space.

* The block names and the declaration keywords
# the vocabulary, all of it registered in plan/package-tree.org.
  - Block names: =title=, =paragraph=, =code=, =heading=, =table=, =header=,
    =row=. A =code= body is opaque; the others may nest.
  - Declaration keywords, written =keyword: value= on their own line right
    under the opening line: =tags=, =language=, =style=, =theme=, =color=,
    =format=, =font=, =level=, =caption=, =column=, =cell=, =row-id=, =meta=.
  - A =heading= takes its depth from its =level:= declaration. Its NUMBER is
    computed, never typed: the first heading is 1, the one under it is 1.1,
    the one under that is 1.1.1, the next at the same level is 1.2, and the
    next top heading is 2.
  - A =table= holds =header= and =row= blocks. A =column:= declaration names
    the column, its type and whether it is optional. A =cell:= with an empty
    value is a MISSING value, and only an optional column may hold one.
  - A =word: value= line whose word is not a registered keyword stays plain
    content. It is never a declaration.
  - The error kinds, all of them severity error with no off switch:
    =stray-text=, =mismatched-end=, =unclosed-block=, =unknown-block-name=,
    =missing-title= and =bad-heading-level=.

* Principles
# one line each, from rules/rule-12-notation-syntax.org and HANDOFF.org.
  - Ordinary things use literal names, not symbols: a title is called title.
  - A named element is opened and closed with one tiny, consistent mark.
  - Goal: insanely easy to read, insanely easy to type, instantly
    understandable by the owner and by agents alike.
  - The smallest slice first: title, paragraph, code block.
  - The editor helps typing, and live rendering hides the marks.
  - Only the hardcore parts (math, graphs) use advanced symbolic syntax:
    tier 3, far future.

* How it fits
# the seams, from plan/architecture.org.
  - The engine surface is called by the editor and the multiplexer, and
    calls nothing back into them.
  - The editor plugs in through the notation-engine boundary, in
    =../contract/=; it triggers the engine build and enters dev mode after.
  - Agents read a notation address carried inside the context bundle.
  - PM installs the notation, then bakes it in (rule 02); it is a package
    with its own kit, like every program.
  - The editor keeps its own features; notation carries none (rule 14).

#+TITLE: kit entry — what PM declares about itself
#+AUTHOR: Shape
# One job: one declarative file saying what PM can do, read by other
# projects and agents. Status: planned only; nothing here is built.
# Source: =../../pm-integration/kit-entry.org= (the capability in
# words); the home is the owner's open question.

* Purpose
- The kit entry is how other projects discover what PM can do at all.
  Today discovery means reading PM's docs: not machine-readable, and it
  drifts from the CLI.
- One file, stable keys: the verbs, the documents they emit, the state
  files an agent may read, where the event feed lives.
* Name and location
- name: =kit-entry=; its file names are registered in step 3
- code: written from the same tables the CLI dispatches on (final home
  is the owner's open question)
- area and layer: =entry= or the new area the owner picks; either way
  nothing below gains a dependency on it
- may require: everything below it
- may be required by: nothing
* Public interface, in plain words
- one document; every claim in it is generated from the dispatch
  tables, so it cannot claim a verb that does not exist.
* What it must never do
- Never hand-written: generated from the tables, or it becomes a second
  source of truth.
- Never the only copy of state: it describes, it does not replace the
  sight files.
* Tests
- the entry's verb list equals dispatch's list, checked mechanically.
* Docs it updates
- the register; =plan/OPEN-DECISIONS.org= (the entry closes).
* Depends on new components
- =mcp-surface-additions= (its rows join the entry's verbs).
* Build order
- After the MCP additions; before =hermes-integration= and the skill
  document PM's capabilities from it.

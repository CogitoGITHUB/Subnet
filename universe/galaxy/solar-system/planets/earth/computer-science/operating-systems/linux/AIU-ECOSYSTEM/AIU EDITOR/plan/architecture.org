#+TITLE: Architecture in the plan — AIU EDITOR
# One job: the named pieces, how they fit, the seams, and what is deliberately absent
# Status: filled 2026-10-16; plans stay general, not yet reviewed.

* The pieces
# the named parts, one line each: what it is and its one job.
  - input — Rust; keys and escape sequences in, adopting the kitty
    keyboard protocol's opt-in flags instead of inventing encoding.
  - drawing — Rust; batched redraws and layout; the screen's one place.
  - buffer and selection — the text state and the modal selection model;
    the exact Racket–Rust seam comes from the study's notes and the first
    build (rule 09).
  - journal — every edit written to disk as it happens, replayable after
    a crash (rule 01).
  - keyboard routes — the keymaps and routes; which layer sees a key
    first (rules 09, 13).
  - commands — what a key means; the config and meaning side; effects
    only at the edges (rule 09).
  - semantic models — what exists, where it sits, what it shows.
  - dashboard — the status and context display; meaning from the Racket
    side, drawing in Rust.
  - agent send — one action; builds the context bundle; calls the AI-link
    boundary; no agent-specific code here (rule 08).
  - live audit — file-change events in; agent or external marks out;
    accept and undo, conflict-safe (rule 07).
  - checkpoint — git checkpoint before agent actions, rollback, and the
    stop switch (rule 07).
  - dev loop — work mode loads config live from source; the bake bakes it
    in as first-class defaults; keep last good; measured start (rule 02).
  - notation seam — hosts the notation engine through the contract
    boundary; can trigger the engine build and enter dev mode after it
    (rule 14).
  - picker seam — Television as the picker; selections flow to sends and
    commands.
  - screen attach — the UI surface: attach, capability negotiation,
    least-capable client wins, batched redraw (from the Neovim UI study).

* How they fit
# the direction of dependency between the pieces, one line per arrow.
  - input → keyboard routes → commands; commands reach the buffer, the
    seams and other effects at the edges.
  - drawing reads state; state never calls drawing.
  - journal sits under every edit, between the buffer and disk.
  - live audit feeds the buffer view; accept and undo act on the journal
    and the checkpoint.
  - agent send → AI-link boundary → adapter (a PM package); nothing agent
    specific is imported by the editor.
  - the dev loop wraps everything: live from source in work mode, baked
    defaults in release.
  - the notation seam is one-way: the editor calls the boundary; the
    loader never asks the notation anything (rule 14).

* The seams
# where another program plugs in, and through which boundary.
  - AIU-NOTATION — the notation-engine boundary (contract step 9);
    engine build trigger, then dev mode (rule 14).
  - AIU TERMINAL MULTIPLEXER — key routing ownership across layers
    (contract/key-routing.org); the editor lives in a pane; terminals are
    the multiplexer's.
  - Agents — the one AI-link boundary with context bundles; adapters as
    pinned, versioned PM packages (rules 07 and 08; agents/ design).
  - PM — install, then bake in (rule 02; pm-integration/install-then-bake).
  - The kit — engine JSON surface, MCP server, skill, read-only plugin
    (ecosystem rule 2; agents/agent-integration-kit).

* Absent on purpose
# parts similar programs carry that this one will not, with the reason.
  A daemon; a plugin runtime; a terminal emulator (the multiplexer holds
  terminals); an agent loop or RAG inside the editor (one boundary only);
  desktop and web frontends; multiplayer.

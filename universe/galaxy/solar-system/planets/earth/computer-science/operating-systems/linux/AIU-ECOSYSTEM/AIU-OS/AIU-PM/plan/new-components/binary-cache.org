#+TITLE: binary cache — build once, reuse by content
#+AUTHOR: Shape
# One job: address a build's result by the content hash of its inputs
# and reuse it. Status: planned only; nothing here is built, and no
# name here may be used by code until the register lists it (step 3).
# Source: =plan/FEATURE-binary-cache.org=.

* Purpose
- Every machine rebuilds what another machine already built. The cache
  turns that into a lookup.
* Name and location
- names: =content-address= and =build-cache= per the FEATURE
- code: =src/store/content-address.rkt=, =src/build/build-cache.rkt=
- area and layer: =store= (8), =build= (10)
- may require: as those areas already may
- may be required by: =entry=
* Public interface, in plain words
- after a build, the result is addressed and stored; a later build
  with the same address is a hit; nothing else changes.
* What it must never do
- Never a hit without a match: the address must fully determine the
  artifact, or the cache lies and installs the wrong thing.
- Never a network dependency for a local build to succeed: a miss is a
  rebuild, not an error.
* Tests
- =tests/build/=, =tests/store/=: same inputs twice, the second is a
  hit; one changed input, a miss.
* Docs it updates
- =plan/NAMING-REGISTER.org=; =plan/FEATURE-binary-cache.org= open
  questions.
* Depends on new components
- the =build-plan= split is done (step 6), so the cache lands in the
  smaller tree; shares the content-address shape with =export-import=.

#+TITLE: Workspace model
# One job: the workspace, the project, and the resource reference — what they
# are, who owns each part, and what survives what.
# Status: written 2026-10-21 from the owner's unified workspace specification;
# the working draft until a program and an adapter both depend on it.

* What this freezes
# the words both programs use, so the editor and the multiplexer mean the
# same thing by "project" and by "resource".
  The workspace is a system object that stands above both programs. It is
  not a session, not a directory, and not a view. It holds projects, and
  through them it points at the resources each program owns.

* The hierarchy
# what sits under what, and what the words mean.
  - Workspace — the top coordination boundary. It holds projects, the
    settings they inherit, the saved presentations, and the references to
    the resources that the programs own.
  - Project — the primary semantic and operational context. A project is a
    unit of work, not a folder: it may name several roots, several
    documents, several workflows, and several terminals. A project does not
    have to be a git repository.
  - Project context — what is being worked on now: the project, the
    resources in hand, the workflows and the documents in play.
  - Resource reference — a stable pointer to something a program owns: an
    editor buffer, an editor tab, a multiplexer tab, a pane, a terminal
    session.
  - Presentation — a saved arrangement of resource references. It names
    what it shows; it does not own what it shows.

* Who owns what
# the one table both programs read; a program never writes another's part.
  - The workspace engine owns: the workspace identity and its settings,
    the project registry and the project settings, the resource references,
    the relationships between resources, the saved presentations, the shared
    context, and the record of cross-program operations.
  - The editor owns: its buffers and their text, its tab order and its
    active tab, its window layout, its point and its selection, and its
    own configuration.
  - The multiplexer owns: its terminal tabs, its panes, its terminal
    sessions, the pty of each session, its window layout, and its own
    configuration.
  - The engine may hold a note of what an application last reported. That
    note is a report, not a second authority: the application that owns the
    resource decides what is true about it.

* Identity
# what a resource is called forever, and what it must never be called by.
  - A workspace and a project have stable identifiers that survive every
    restart, and a name beside them that the owner may change.
  - A resource reference has a stable identifier of its own, the kind of
    resource it names, the program that owns it, and the workspace and
    project it belongs to.
  - A process id, a socket path, a memory address and a pane number are
    NOT identity. They are observations of one run, and they are never the
    only name of a thing.
  - A resource reference carries a status: live, stale, gone. A reference
    that was registered once is not a claim that the thing is there now.

* What survives what
# the lifecycle guarantee, in both directions.
  - Closing the editor leaves the workspace, the projects and the
    multiplexer resources alone. Closing the multiplexer leaves the
    workspace, the projects and the editor resources alone.
  - Restarting either program loses nothing in the workspace: the engine
    reads it back from disk.
  - While a program is not running, its resources are marked unavailable.
    The workspace says so plainly rather than pretending they are there.
  - Three deletions are three operations and never one:
    - unregistering a reference forgets the pointer; it does not stop the
      process, close the tab or delete the file;
    - removing a project forgets the project and its references; it does
      not close a terminal or delete a buffer;
    - deleting a workspace forgets the workspace itself. It still never
      closes another program's resources.
  - A program's own resources die with that program only when that program
    is told to end them, and never because the other program asked about
    them.

* Persistence
# where the truth of the workspace lives and how it stays whole.
  - The workspace lives in files in one state directory, and the state
    directory is an argument. No environment variable names it.
  - The files carry a schema version. A file with a newer version is
    refused, not downgraded and not silently overwritten.
  - A write is: write the new file beside the old one, then rename it over
    the old one. A reader therefore sees the old file or the new file, and
    never half of one.
  - One writer at a time: the writer takes a lock, writes, and releases it.
    A writer that finds the lock held says the lock is busy and waits on
    the event that ends the wait. Nothing polls and nothing ticks.
  - A read takes no lock: the rename makes a read whole.
  - A file that cannot be parsed is reported as broken and is never
    replaced by an empty one. The broken file is kept for the owner.

# One job: make PM's actions callable from Hermes, with the skill half
# and the plugin half saying what each action is. Status: planned only;
# nothing here is built. Source:
# =../../pm-integration/hermes-integration.org= (the capability in

* Purpose
- Every project ships its agent surfaces; PM has none on the Hermes
  side. Hermes must read PM state and run PM actions the same way the
  OpenCode plugin and MCP tools do today: through the same documents,
  with the same read-free / mutate-gated rule.
* Name and location
- name: the Hermes surface of =pm=; its file names are registered in
  step 3
- code: beside the existing surfaces under =agent/= (where the OpenCode
  plugin and skill already live); any new Racket is tool rows, not a
  second implementation
- area and layer: the surfaces are docs beside the CLI; their Racket
  side is the owner's open question (where the agent-side components
  live)
- may require: =entry='s documents and MCP tools, like every surface
- may be required by: nothing
* Public interface, in plain words
- the same verbs every surface gets: status, events tail, and the gated
  commands; read is free, mutate asks the human.
* What it must never do
- Never a second implementation of any decision: it calls the same
  documents and tools as the CLI and the MCP server.
- Never a state-changing action without the confirmation door.
* Tests
- beside the surface, like the OpenCode plugin's test.
* Docs it updates
- =plan/OPEN-DECISIONS.org= (the Hermes entry closes);
  =plan/NAMING-REGISTER.org=.
* Depends on new components
- =mcp-surface-additions= (the verbs it exposes) and =kit-entry= (how
  it discovers what PM can do).
* Build order
- After the MCP additions; same turn as the OpenCode skill if possible:
  the four surfaces ship together.
